## `D.<Class>(props)`

:::caution
**props 테이블은 일회용입니다 — 다시 쓰는 것은 정의되지 않은 동작입니다.** `D.<Class>{…}`(와 `q.Dispatch.drive`)는 그 테이블을 제자리에서 **소진**합니다: 안의 `OnCreated`/`OnRendered`/Modifier는 처리된 표시로 바뀌고, 그 뒤 그 테이블은 쓴 것입니다. 같은 테이블을 두 번째 인스턴스에 넘기면 에러 없이 그 훅들이 빠지고, **같은 인스턴스에 다시 넘기는 것도 지원하지 않습니다**(핸들러마다 "이미 소진된 테이블이 또 올 수 있다"를 생각하며 짜게 하지 않으려는 설계 — 게이트도 두지 않습니다). 인스턴스마다 새 테이블을 만드세요(함수로 감싸면 자연히 그렇게 됩니다).
:::

**시그니처**

```luau
-- 클래스마다 하나씩 생성된 별칭. Frame이라면:
D.Frame: (FrameParam<FrameElem>) -> Frame

-- props 테이블의 모양(생성 타입 — 클래스마다 프로퍼티·이벤트 목록이 다르다)
export type FrameParam<E> = {
	[number]: E,       -- 숫자 키: 자식과 디스크립터
	Size: PV8?,        -- 문자 키: 프로퍼티
	Visible: PV0?,
	-- …
	MouseEnter: (((x: number, y: number) -> ()) | StateMarker<(x: number, y: number) -> ()> | None)?,
	-- …
}
```

**인자** — props 테이블 하나. 문자 키와 숫자 키가 **한 테이블에 섞여** 들어갑니다.

**반환** — 만들어진 Instance. 타입은 그 클래스 그대로(`D.Frame`은 `Frame`).

**예제**

```luau
local hovered = q.Source(false)
local label = q.Source("확인")
local ref = q.PreRef<<TextButton?>>(nil)

local button = D.TextButton({
	-- 문자 키 — 프로퍼티와 이벤트
	Text = label,                                   -- State: 값이 바뀌면 프로퍼티가 따라간다
	Size = UDim2.fromOffset(120, 36),               -- 평범한 값
	BackgroundColor3 = hovered:Compute(function(self: q.StateData<boolean>): Color3
		return if self:Get() then Color3.fromRGB(60, 130, 255) else Color3.fromRGB(30, 30, 30)
	end),
	TextTransparency = q.Tween({ Value = 0, Time = 0.2 }), -- Tween 값
	MouseEnter = function()                          -- 이벤트: 엔진 인자만 받는다
		hovered:Set(true)
	end,
	MouseLeave = function()
		hovered:Set(false)
	end,
	UICorner = 6,                                    -- 숏핸드 키

	-- 숫자 키 — 자식·Modifier·Ref·디스크립터
	D.UIPadding({ PaddingLeft = UDim.new(0, 8), PaddingRight = UDim.new(0, 8) }),
	D.Modifier.TextButton():TextSize(18),
	ref,
	q.Tag("primary"),
	q.OnChange("Text", function(v: string)
		print(v)
	end),
})

button.Parent = script.Parent -- 붙이는 것은 props가 아니라 밖의 한 줄
```

**동작 — 만들어지는 순서**

1. 엔진에 Instance를 만든다.
2. quad가 그 Instance를 **소유**한다(생명주기 바인딩의 전제 — [Claim과 D.Mapper](/reference/roblox/04-claim-mapper/)의
   "한 번만 claim한다").
3. props를 드라이브한다. 첫 패스에서 숫자 키의 `Modifier`가 소진되고(아래), 그다음 **숫자 키가
   문자 키보다 먼저** 처리됩니다. `OnChange`가 같은 props의 프로퍼티 쓰기를 받아볼 수 있는 것이
   이 순서 덕입니다([q.OnChange](/reference/roblox/05-onchange/)의 초기값 발화).

`D.Frame` 같은 별칭은 사실 `D.New("Frame")`을 한 번 적용해 둔 것이고, 둘은 같은 파이프라인을 탑니다.

## 문자 키 — 프로퍼티와 이벤트

**프로퍼티 값의 대수**

| 넣는 것 | 뜻 |
|---|---|
| 값 그대로 | 한 번 쓴다 |
| [`State`](/reference/core/03-state/)(= `Source`/파생 State) | 발행될 때마다 다시 쓴다 |
| `q.Tween{ … }` | 그 값으로 애니메이션한다([Tween과 Animate](/reference/roblox/06-tween-animate/)) |
| [`q.None`](/reference/core/10-lifetime-sentinels/#qnone) | 그 자리를 `nil`로 쓴다 — 객체 참조(`Adornee`/`NextSelection*` 등)를 놓는 방법 |

**`Tween` 팔이 있는 타입은 정해져 있습니다** — `number` · `boolean` · `UDim` · `UDim2` · `Vector2` ·
`Vector2int16` · `Vector3` · `Color3` · `CFrame` · `Rect`. 그 밖의 타입(`Enum.*`, `string`, Instance 참조 등)의
프로퍼티는 값 / `State` / `None` 셋뿐이고, 거기에 `Tween`을 넣으면 타입 에러입니다.

`None`으로 쓴 `nil`을 받아들이지 못하는 프로퍼티라면 엔진이 자기 에러를 던지고, 그 에러는 여러분이
봐야 할 에러입니다 — quad는 삼키지 않습니다.

**이벤트**

이벤트 이름을 키로 쓰면 그 신호에 연결됩니다. 콜백은 **엔진 인자만** 받습니다 — `self`도, Instance도
앞에 붙지 않습니다.

```luau
D.TextButton({ Activated = function(inputObject: InputObject, clickCount: number) end })
```

값 자리에는 콜백 / `State<콜백>` / `None`이 올 수 있습니다. `None`(또는 State가 계산한 `nil`)이면 그
자리의 연결을 끊고 새로 연결하지 않습니다. 같은 자리에 다른 콜백을 다시 발행하면 옛 연결을 끊고
하나만 남깁니다(`Connect`는 멱등이 아니라서 같은 값 dedup이 없습니다 — 재발행마다 Disconnect+Connect 한 번).

**`AncestryChanged`의 둘째 인자 `parent`는 `Instance?`입니다.** 인스턴스가 트리에서 빠질 때 엔진이 `nil`을 주므로 생성 타입도 그렇게 나옵니다 — `function(child: Instance, parent: Instance)`로 주석하면 타입 에러이고, 본문에서 `nil`을 먼저 거르세요(`q.OnChange("Parent", …)`의 콜백 인자도 같습니다 — [05-onchange](/reference/roblox/05-onchange/)).

**타입 검사는 인자가 모자란 콜백을 잡지 않습니다.** Luau의 함수 서브타이핑 규칙상 `MouseEnter =
function(x) end`이나 `MouseEnter = function() end`처럼 선언보다 **적게** 받는 함수는 에러가 아닙니다
(엔진이 넘긴 나머지 인자를 버릴 뿐입니다). 인자가 **더 많거나** 타입이 다르면 그때는 잡힙니다.

함수가 아닌 값이 오면 quad가 먼저 거부합니다.

```
Event: handler for "{k}" must be a function (got {typeof(v)})
```

(엔진은 이 자리에서 던지지 않고 출력 창에만 남기기 때문에, 게이트가 quad 쪽에 있습니다.)

**어떤 키가 매치되는가**

프로퍼티인지 이벤트인지는 **엔진 리플렉션**으로 판정합니다 — 그 클래스(상속 포함)의 쓰기 가능한
프로퍼티면 프로퍼티 핸들러가, 이벤트면 이벤트 핸들러가 받습니다. 두 집합은 서로 겹치지 않습니다.
읽기 전용 프로퍼티(`AbsoluteSize` 등)는 쓰기 표면이 아니라 여기서 매치되지 않습니다 — 읽고 싶으면
[`q.OnChange`](/reference/roblox/05-onchange/)를 쓰세요.

둘 다 아닌 문자 키는 일반 no-match 에러입니다.

```
Dispatch: no handler matched key {tostring(k)} (value: {typeof(v)}{, brand: …}) — check that the provider for this value (e.g. quad-roblox) is initialized
```

**`Parent`는 props가 아닙니다**

`Parent` 키는 **어떤 핸들러에도 매치되지 않도록** 프로퍼티 핸들러의 매치 규칙에서 빠져 있습니다.
그래서 `Parent`를 넣으면 특별한 문구가 아니라 위의 일반 no-match 에러가 납니다. 부모는 만들어진
뒤 밖에서 `inst.Parent = …` 한 줄로 붙이세요.

**각 클래스의 프로퍼티·이벤트 목록**

quad는 Roblox 클래스를 **설명하지 않습니다** — React가 `<div>`의 속성을 설명하지 않는 것과 같습니다.
`Frame`에 어떤 프로퍼티가 있고 `TextButton`에 어떤 이벤트가 있는지는 Roblox 공식 레퍼런스가 소스입니다.

> `https://create.roblox.com/docs/reference/engine/classes/<Class>`
> (예: `.../classes/Frame`, `.../classes/TextButton`)

quad가 더하는 것은 그 위의 **값 대수**(State/Tween/None)와 숫자 키 자리뿐입니다. 이름과 타입은 생성
타입이 그대로 실어 나르므로 에디터 자동완성에서도 보입니다.

:::caution 레거시 프로퍼티
엔진이 레거시로 표시한 프로퍼티도 **일부는** 생성 타입에 남아 있습니다 — v1 코드를 옮길 때
자동완성이 끊겨 이름 자체를 못 쓰는 일이 없도록 남긴 것이고, 남은 필드에는 표시가 붙습니다.

```luau
--- ⚠️ **deprecated** — Roblox Hidden
Font: PV35?, -- @deprecated (Roblox Hidden)
```

**둘 다 이름 허용목록입니다.** `Deprecated`도 `Hidden`도 태그 통째가 아니라 **자주 쓰이던 이름만**
남깁니다 — 기준은 "v1 코드를 옮길 때 재작성 노고가 큰가"이고, 소문자 별칭(`className`·`focus`)처럼
quad v1 이전의 유물이나 잘 안 쓰이던 것(`Draggable`, `BillboardGui`의 거리 한계 둘)은 빠집니다.
Roblox가 Deprecated로 표시한 동작은 quad가 보장할 것이 없습니다(예: `className`의 변경 시그널은
만들어지지만 발화하지 않는 죽은 시그널). `VideoFrame.InternalVideoUsage` 같은 내부용 Hidden과
`Deprecated`이면서 `Hidden`인 옛 별칭(`archivable`·`Localize`, `BackgroundColor` 같은 BrickColor 쌍둥이)도
허용목록에 없어 빠집니다. `NotScriptable`은 예외 없이 빠집니다.

그래서 **쓰기 표면**(props 문자 키와 [Modifier setter](/reference/roblox/03-d-modifier/))에 남아 있는 레거시
프로퍼티는 넷입니다.

| 프로퍼티 | 태그 | 있는 곳 |
|---|---|---|
| `Font` | Hidden | `TextLabel`·`TextButton`·`TextBox` |
| `Transparency` | Hidden | GuiObject 계열 |
| `FontSize` | Deprecated | `TextLabel`·`TextButton`·`TextBox` |
| `TextWrap` | Deprecated | `TextLabel`·`TextButton`·`TextBox` |

읽기 표면([`q.OnChange`](/reference/roblox/05-onchange/))에는 레거시 이름이 없습니다(한때 `className`이 있었으나
그 변경 시그널이 실기기에서 발화하지 않아 뺐습니다).

**⚠️ 에디터는 작성 지점에서 경고해주지 않습니다.** 필드 위 `---` 독 주석은 **멤버 접근 hover**
(`mod:Font(...)` 같은 자리)에만 실립니다. `D.TextLabel({ Font = … })`처럼 **테이블 리터럴 키를
자동완성**할 때는 documentation도 deprecated 태그도 실리지 않습니다.
Luau의
`@deprecated` 속성이 함수 전용이라 테이블 타입 필드에는 아예 붙일 수 없고 주석이 유일한 채널이기
때문입니다 — 즉 작성 지점 경고나 린트는 불가능하고, 그 몫은 문서에 있습니다.

무엇으로 갈아타야 하는지는 위의 Roblox 공식 레퍼런스가 소스입니다(예: `Font` → `FontFace`).
:::

## 숫자 키 — 자식과 디스크립터

숫자 키에 놓는 Instance는 **quad가 소유한 것**이어야 합니다 — `D.<Class> { … }`로 만들었거나 [`Claim`](/reference/roblox/04-claim-mapper/)으로 넘겨받은 것. `Instance.new`나 다른 라이브러리가 만든 인스턴스를 그대로 놓으면 `InstanceChild: this Instance is not claimed by quad — build it with the Declaration or take it over with Claim first (an Instance made by another quad module instance also counts as not claimed here, and so does a destroyed one — a destroyed Instance cannot be reused)`로 거부됩니다(그 인스턴스가 밖에서 파괴돼도 quad가 알 수 없기 때문입니다). 꼬리 구절대로, 다른 quad 인스턴스(`q.New()`를 따로 부른 코드나 `quad_base` 사본이 둘인 프로젝트)가 만든 Instance도 이쪽에는 미claim입니다. `Slot`의 원소도 같은 규칙입니다.

**자리를 쥔 `State`에 거부될 값을 넣으면 그 자리는 빈 채로 남습니다.** `D.Frame { src }`의 `src:Set(x)`에서 `x`가 미claim 인스턴스이거나 다른 자리에 이미 앉은 인스턴스이면 에러가 나지만, 그때는 옛 자식이 이미 내려간 뒤입니다 — 자리는 옛 값의 철거 → 새 값의 처리 순서로 돌고, 거부는 새 값의 처리에서 납니다(그 자리가 `Slot`을 쥐고 있었으면 그 트리도 이미 언마운트됐습니다). 에러는 시끄럽게 나므로 조용히 어긋나지는 않지만, 그 에러를 pcall로 삼키고 계속 가면 "자리 하나가 빈 채 값만 옮겨간" 상태가 남습니다. 두 자리의 자식을 맞바꾸려면 `s1:Set(c2); s2:Set(c1)`이 아니라 **둘 다 먼저 `:Set(nil)`로 비우고** 채우세요.

숫자 키 자리에는 자식 Instance와 **디스크립터**들이 들어갑니다. 이 자리에 올 수 있는 값은
이만큼입니다.

| 값 | 무엇을 하나 |
|---|---|
| Instance | 정적 자식으로 붙는다 — quad가 만든(또는 `Claim`한) 것만, 그리고 한 번에 한 자리에만(같은 Instance를 두 부모에 놓거나 `{ c, c }`로 놓으면 둘째가 거부됩니다; 앉아 있는 동안 `q.dispose`도 거부) |
| [`Slot`](/reference/core/06-slot/) | 동적 자식 구간 — 목록/단일 교체 |
| [`Ref` / `PreRef` / `PostRef`](/reference/core/07-ref/) | 만들어진 Instance를 그 핸들에 채운다 |
| [`Observer` / `Effect`](/reference/core/05-observer-effect/) | 그 Instance의 생애에 묶인다(leaf 종료 관용구) |
| [`Modifier`](/reference/core/08-modifier/) | 프로퍼티 묶음을 이 자리에 펼친다(아래) |
| [`q.Tag(...)` / `q.Attr{...}` / `q.StringAttr`·`NumberAttr`·`BooleanAttr`](/reference/core/09-tag-attr/) | CollectionService 태그·Attribute |
| `q.OnChange(name, fn)` | 프로퍼티 변경 신호 바인딩 |
| [`q.None`](/reference/core/10-lifetime-sentinels/#qnone) | 아무것도 아닌 자리(구멍 메꾸기) |
| 위의 것들을 담은 `State` | 발행될 때마다 그 자리를 갈아 끼운다 |

`Modifier`·`Ref`류·`Observer`·`Slot` 같은 **핸들러 층 값은 문자 키가 아니라 숫자 키 자리에** 놓습니다.

**nil 구멍을 만들지 마세요 — `or q.None`**

배열 리터럴 중간에 `nil`이 들어가면 배열 순회가 끊겨 부기(bookkeeping)가 깨집니다. 조건부 자리는
[`q.None`](/reference/core/10-lifetime-sentinels/#qnone)으로 메꾸는 것이 관용구입니다.

```luau
D.Frame({
	props.Modifier or q.None,
	props.Child or q.None,
})
```

**Modifier는 첫 패스에서 소진됩니다**

숫자 키 자리의 `Modifier`는 드라이브 첫 패스에서 자기 필드를 **문자 키로 펼치고** 그 자리를
비웁니다. 규칙 둘:

- **인라인 문자 키가 이깁니다** — 같은 이름이 props에 직접 적혀 있으면(그 값이 `None`이어도) 그쪽이 남습니다.
- **뒤에 오는 Modifier가 이깁니다** — 숫자 키의 나중 자리가 먼저 씁니다.

문자 **키의 값**으로 Modifier를 놓는 것은 오용이라 바로 거부합니다.

```
Modifier: a Modifier cannot be a value of key "{tostring(k)}" — place it in the array part
```

**클래스별로 좁혀집니다**

숫자 키 자리의 타입은 클래스마다 다릅니다. `Ref`는 **그 클래스(또는 조상)의 Ref만** 받고, `Modifier`도
자기 클래스와 조상 클래스의 것만 받습니다.

```luau
local frameRef = q.Ref<<Frame?>>(nil)
local labelRef = q.Ref<<TextLabel?>>(nil)

D.Frame({ frameRef })  -- OK
D.Frame({ labelRef })  -- 타입 에러: 형제 클래스의 Ref는 거부된다
```

[`D.Mapper`](/reference/roblox/04-claim-mapper/) 디스크립터는 `Claim` 전용이라 여기 오면 no-match입니다.

## 숏핸드 키 넷

GuiObject 계열 클래스에는 자주 쓰는 UI 자식을 문자 키로 줄여 쓰는 편의 키가 넷 있습니다.

| 키 | 값 | 하는 일 |
|---|---|---|
| `UICorner` | `number` 또는 `UDim` | 관리되는 `UICorner` 자식의 `CornerRadius`. number는 offset UDim으로 바뀐다 |
| `UIPadding` | `UDim` | 관리되는 `UIPadding` 자식의 네 방향 패딩 |
| `UIPaddingOffset` | `number` | 같은 자식의 네 방향 패딩을 offset UDim으로 |
| `UIScale` | `number` | 관리되는 `UIScale` 자식의 `Scale` |

```luau
D.Frame({ UICorner = 8, UIPaddingOffset = 12 })
```

- 값 자리에 `State`와 `Tween`이 그대로 들어갑니다(같은 값 대수).
- `UIPadding`과 `UIPaddingOffset`은 **같은 관리 자식**을 공유합니다 — 한 인스턴스에 둘을 같이 쓰지
  마세요. 둘 다 문자 키라 처리 순서가 테이블 순회 순서를 따르고(Modifier에 든 쪽이 인라인 키보다
  나중에 처리될 수도 있습니다), 그래서 어느 쪽이 이기는지는 **정해져 있지 않습니다**.
- 값이 `nil`/`None`이 되면 그 관리 자식을 파괴합니다.
- 관리 자식은 quad가 만든 것이고, 여러분이 직접 넣은 `UICorner` 자식은 건드리지 않습니다. 다만
  템플릿의 `UICorner`와 이 숏핸드를 같이 쓰면 둘이 생기니 하나만 쓰세요.

## `D.New<<T>>(className)(props)`

**시그니처**

```luau
New: <T>(className: string) -> (props: any) -> T
```

`D`에 별칭이 없는 클래스를 만드는 이스케이프 해치입니다. 커링이라 두 번 부릅니다.

```luau
local part = D.New<<Part>>("Part")({ Name = "loose", Anchored = true })
```

- **타입 인자를 명시하세요.** 생략하면 반환이 `unknown`으로 추론됩니다.
- **props는 `any`입니다** — 클래스별 프로퍼티 검사가 없습니다. 오타든 없는 프로퍼티든 런타임에서야
  드러납니다. 별칭이 있는 클래스라면 별칭을 쓰세요.
- 파이프라인은 별칭과 완전히 같습니다(생성 → 소유 → 드라이브). 에러 blame도 여러분의 호출 줄에 닿습니다.

## `q.Declaration` — 네임스페이스와 생성되는 클래스

`q.Declaration`은 `UseProvider`가 병합해 준 생성 네임스페이스입니다. 안에 있는 것은 넷입니다.

| 멤버 | 무엇 |
|---|---|
| `D.<Class>` | 클래스별 생성 별칭 — 아래 31개 |
| [`D.New`](#dnewtclassnameprops) | 범위 밖 클래스용 이스케이프 |
| [`D.Mapper`](/reference/roblox/04-claim-mapper/) | 이미 있는 트리를 매핑하는 디스크립터 생성기 |
| [`D.Modifier`](/reference/roblox/03-d-modifier/) | 클래스별 타입드 Modifier 생성자 |

클래스 별칭은 **31개**입니다.

`BillboardGui` · `Camera` · `CanvasGroup` · `Folder` · `Frame` · `ImageButton` · `ImageLabel` ·
`ScreenGui` · `ScrollingFrame` · `SurfaceGui` · `TextBox` · `TextButton` · `TextLabel` ·
`UIAspectRatioConstraint` · `UICorner` · `UIDragDetector` · `UIFlexItem` · `UIGradient` ·
`UIGridLayout` · `UIListLayout` · `UIPadding` · `UIPageLayout` · `UIScale` · `UIShadow` ·
`UISizeConstraint` · `UIStroke` · `UITableLayout` · `UITextSizeConstraint` · `VideoFrame` ·
`ViewportFrame` · `WorldModel`

서비스와 추상 클래스(`GuiObject` 등)는 범위 밖이고, 엔진이 Deprecated/NotBrowsable/Internal로 표시한
클래스도 제외됩니다. 목록에 없는 클래스는 `D.New<<T>>(className)`으로 만드세요.
