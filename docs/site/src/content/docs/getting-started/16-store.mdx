import { Quiz, QuizResults } from 'starlight-quiz/components';

> **대상 독자**: [15. 층을 건너 값 넘기기](/getting-started/15-context/)를 끝낸 개발자
> **목표**: 카운터의 보폭(+1)을 흩어진 지역 변수 대신 이름 붙은 묶음 하나로 두고, 진입점에서 바꾸면 모든 카운터가 따라가게 만들기

지금까지 값이 하나 필요할 때마다 `q.Source`를 하나씩 만들었습니다. 값이 여러 개로 늘면 그것들을 낱개 변수로 흩어 두기보다 **이름 붙은 묶음 하나**로 갖고 다니는 게 낫습니다. `q.Store`가 그 묶음입니다.

---

## 1. `Store`는 새 노드가 아니라 이름 붙은 가방입니다

**`Store`는 반응형 그래프에 사는 새 노드가 아닙니다.** 이미 있는 `Source`들을 한 테이블에 담아 `store.Step`처럼 점으로 꺼내 쓰게 해 주는 것이 전부입니다. 진입점에 카운터 설정을 담을 Store를 하나 만듭니다.

```luau
-- (Main.client.luau 계속)
const settings = q.Store({
    Step = q.Source(1),
})
```

`settings.Step`은 **넣은 그 `Source` 객체 자신**입니다 — 래퍼가 아니라서 지금까지 배운 `:Get`/`:Set`/`:Compute`가 그대로 통합니다.

```luau
print(settings.Step:Get())   --> 1
settings.Step:Set(5)
```

---

## 2. 15장의 가방에 그대로 실어 보내기

`Store` 하나를 위해 새 전달 경로를 만들 필요는 없습니다. **15장에서 이미 만든 `ctx`에 열쇠를 하나 더 `:Set` 하면 됩니다** — `:Set`이 가방 자신을 바꾸고 자기를 돌려주는 체이닝이라는 것은 15장 4절에서 봤습니다.

먼저 이 설정의 열쇠 모듈을 하나 만듭니다. `Theme` 모듈과 모양이 똑같습니다.

```luau
-- 새 파일: ReplicatedStorage/Client/UI/Settings
const q = require("./Quad")

return {
    Provider = q.Context.Provider("Settings"),
}
```

진입점에서 `ctx`를 만들던 줄에 `:Set`을 하나 이어 붙입니다.

```luau
-- (Main.client.luau 계속 — 15장에서 만든 ctx 줄을 이렇게 고칩니다)
const Settings = require("@game/ReplicatedStorage/Client/UI/Settings")

const ctx = q.Context()
    :Set(Theme.Provider, { Accent = Color3.fromRGB(0, 162, 255) })
    :Set(Settings.Provider, settings)
```

**`CounterBoard.luau`는 한 글자도 바뀌지 않습니다.** 14장에서 만든 그 컴포넌트는 애초에 `props.Ctx`를 열어 보지 않고 `Counter`에 그대로 넘기기만 했으므로([15장 2절](/getting-started/15-context/)), 가방 안의 열쇠가 하나 늘어도 중간 층이 손댈 일이 없습니다. `Store`가 "값 여럿을 몰아 넣는" 쪽에 잘 맞는 이유가 이것입니다 — 값이 늘 때마다 새 `Provider`와 새 전달 경로를 만드는 대신, 이미 뚫려 있는 가방 하나에 이름만 늘립니다.

---

## 3. 말단이 자기 몫을 꺼내 쓴다

`Counter`에서 `Theme`을 꺼내던 것과 똑같은 방식으로 `Settings`도 꺼냅니다 — **같은 `ctx`, 다른 열쇠**입니다.

```luau
-- … (Counter.luau) 파일 머리에 한 줄 더
const Settings = require("./Settings")

return function(props)
    const theme = props.Ctx:Get(Theme.Provider)
    const settings = props.Ctx:Get(Settings.Provider)   -- ← 같은 가방에서 다른 열쇠로 하나 더
    const count = q.Source(props.Start or 0)

    -- …중간 생략…
```

버튼의 `Activated`에서 고정돼 있던 `+ 1`을 `settings.Step`으로 바꿉니다.

```luau
-- … (Counter.luau) 버튼의 Activated를 이렇게 고칩니다
            Activated = function()
                count:Set(count:Get() + settings.Step:Get())
            end,
```

마지막으로 그 보폭을 바꿀 수 있는 버튼을 진입점에 하나 답니다. `settings`는 진입점이 직접 만든 값이니 `Context` 없이 바로 씁니다.

```luau
-- (Main.client.luau 계속 — board 뒤에)
const stepButton = D.TextButton {
    Size = UDim2.fromOffset(120, 32),
    Text = settings.Step:Compute(function(s)
        return `보폭: {s:Get()}`
    end),
    Activated = function()
        settings.Step:Set(settings.Step:Get() % 5 + 1)   -- 1→2→…→5→1
    end,
}
stepButton.Parent = screen
```

**실행하면** "보폭: 1" 버튼이 하나 뜨고, 누를 때마다 2, 3, 4, 5, 1로 돌아갑니다. 그 뒤로 아무 카운터나 눌러 보면 오르는 폭이 방금 정한 숫자를 따라갑니다 — `Counter.luau`도 `CounterBoard.luau`도 다시 건드리지 않았는데, 진입점에서 바꾼 값 하나가 목록의 카운터 전부에 퍼집니다. 15장에서 `Accent` 하나로 봤던 것과 같은 그림이고, 이번엔 값이 하나가 아니라 **이름 붙은 묶음**이라는 것만 다릅니다.

<details>
<summary><strong>계산된 이름으로 필드를 만들고 싶다면요?</strong></summary>

지금까지처럼 필드 이름을 코드에 직접 적는다면 생성자에 넣는 것으로 충분합니다. 이름이 런타임에만 정해지는 경우(서버가 준 키 목록 등)를 위한 문이 하나 더 있습니다 — `store:Of<<T>>(name)`입니다. 없는 이름이면 그 자리에서 `Source<T>`를 만들어 저장하고, 같은 이름으로 다시 부르면 같은 객체가 돌아옵니다. 갓 만들어진 값은 `nil`이라 바로 `:Set`해야 하고, 타입 인자 `T`는 검사되지 않는 캐스트입니다. `Of`/`Names`와 밑줄 둘(`__`)로 시작하는 이름은 필드로 못 씁니다 — 앞의 둘은 메소드 이름이고 뒤는 팬텀 필드 자리라 생성자와 `:Of` 둘 다 거부합니다. 전체 표면은 [레퍼런스: `Store`](/reference/core/04-store/)에 있습니다.

</details>

<details>
<summary><strong>컴포넌트 안에서 만든 <code>Source</code>/<code>Store</code>는 누가 정리하나요?</strong></summary>

딱히 부를 것이 없습니다. `q.Source`도 `q.Store`도 평범한 Luau 테이블이라, 더 이상 아무도 참조하지 않으면 다른 테이블과 똑같이 가비지 컬렉트됩니다. 진입점이 계속 들고 있는 `settings`는 계속 살아 있고, `Counter` 안에서 그때그때 만드는 `count`는 그 카운터가 파괴되고 아무도 안 붙잡으면 같이 사라집니다.

**인스턴스에 매달린 값**만 다릅니다 — 프로퍼티에 꽂힌 값이나 자리에 놓인 `State`처럼 인스턴스가 사는 동안 붙들려 있어야 하는 것들은, `q.Backend.bindLifetime`이라는 별도 프리미티브로 그 인스턴스에 강하게 묶입니다([레퍼런스: 생명주기와 센티널](/reference/core/10-lifetime-sentinels/)). 지금까지 써 온 자리는 전부 quad가 알아서 이 프리미티브를 불러 준 경우였습니다 — `Store` 자신은 이 부류가 아닙니다.

</details>

## 이해 점검

<Quiz title={"Store가 하는 일"}>

`q.Store({ Step = q.Source(1) })`를 만들 때 실제로 일어나는 일로 옳은 것은 무엇인가요?

- [ ] `Step`이라는 이름의 새 반응형 노드가 하나 생기고, 그 안에 넘긴 `Source`가 감싸입니다
- [x] 넘긴 `Source`가 `store.Step` 자리에 그대로 들어앉고, `Store`는 그것들을 이름으로 묶는 가방일 뿐입니다
- [ ] `Store`가 필드를 전부 하나로 합쳐 `:Compute`로 파생시킨 새 `State`를 돌려줍니다

`Store`는 반응형 그래프에 사는 새 노드가 아닙니다. 이미 만든 `Source`들을 한 테이블에 담아 점 접근을 주는 것이 전부라, `store.Step`은 넣은 그 `Source` 객체 자신입니다.

</Quiz>

<Quiz title={"가방에 열쇠를 하나 더"}>

같은 `ctx`에 `Settings.Provider`를 하나 더 `:Set` 했을 때 `CounterBoard.luau`를 그대로 둬도 되는 이유는 무엇인가요?

- [ ] `CounterBoard`가 `q.Context`를 구독하고 있어서 새 열쇠가 생기면 알아서 반영하기 때문입니다
- [x] `CounterBoard`는 `props.Ctx`를 열어 보지 않고 그대로 `Counter`에 넘기기만 해서, 가방 안의 열쇠 수와 무관하기 때문입니다
- [ ] `Settings.Provider`와 `Theme.Provider`가 같은 이름을 공유해 `CounterBoard`가 이미 알고 있었기 때문입니다

15장에서 본 것과 같습니다 — 중간 층은 가방을 그대로 건네기만 하고 안에 뭐가 들었는지 모릅니다. 그래서 가방에 열쇠가 늘어도 중간 층의 코드는 바뀔 이유가 없습니다.

</Quiz>

<Quiz title={"선언 안 한 키를 점으로 읽으면"}>

`settings.Label`처럼 생성자에 넣지 않은 키를 점으로 읽으면 어떻게 되나요?

- [ ] 그 자리에서 새 `Source(nil)`이 만들어져 저장되고 그것이 돌아옵니다
- [x] `nil`입니다 — 점 접근에는 지연 생성이 없고, 없는 이름을 만들어 주는 문은 `:Of` 하나뿐입니다
- [ ] `Store: "Label" is a reserved store key` 에러가 그 자리에서 납니다

점 접근으로 없는 이름을 읽으면 그냥 `nil`입니다. 계산된 이름으로 필드를 지연 생성하는 유일한 문은 `store:Of<<T>>(name)`입니다.

</Quiz>
