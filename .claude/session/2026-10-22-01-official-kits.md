# 2026-10-22-01 — 킷 둘을 quad 공식 지원 킷으로 (방향 합의, 구조는 논의 중)

`session/2026-10-20-02-round15-quality.md` §13 뒤 같은 긴 세션의 이어짐(2026-10-21 밤 devplorer 갈아타기 후보 묶음 — 검색 목록·가상 표·BlockingCount·단추 크기·작은 쪽 끌기·메뉴 폭 — 이 끝난 다음 사용자가 꺼낸 다른 주제). 코드 변경 없음.

## 1. 사용자 제기 → 메인 의견

사용자: devui 킷과 material(M3) 킷을 quad 레포에서 지원해야 할까. 지지 근거 — *"우리처럼 작(지는 않지만)은 개인 프로젝트의 경우 신뢰도 문제가 있어서, 여럿 나뉘여 있어버리면 업데이트를 받을 수 있을까? 에 걸리게 된단 말이야, 그런데 중앙에서 관리하고 계속 최신에 맞게 업데이트 해준다 하면 그것만으로도 사실 더 신뢰도 있어보고, 또 바로 사용하는데 있어 사용해볼 키트가 눈 앞에 있다는것 만으로도 도움이 된다고 생각해. 시제품을 만들어 보며 배울 수도 있고"*. 더 늘리진 않고 둘.

메인 의견(채팅): 찬성. 근거 — 같은 릴리즈로 함께 올라가는 것 자체가 호환 약속, 그리고 두 킷이 지금까지 본체 공개 표면의 빈 곳을 가장 많이 찾았다(Spread 확장은 devui `InputText`, 렌더 스텝 op 근거는 material `Heartbeat` 일곱 번, Declaration 타입). 비용: 본체 breaking마다 두 킷 수정, 레포 정체성(렌더러 라이브러리가 UI 프레임워크 제품처럼), material 범위가 끝없음. 조건 셋 권고: (1) 킷은 quad 공개 표면만 쓴다 — 기계 검사로, (2) 지원 범위 명시 — 본체와 lockstep 버전, "필요에 따라 넓히는 참고 킷"(완전 커버리지 약속 없음), 공식 킷은 둘로 끝, (3) ROADMAP의 패키지화 선결 둘(소비 쪽 pesde 의존성, 킷만 떼어 쓸 때 안쪽 `require`)을 먼저. material 이름·아이콘 라이선스 표기 확인 한 줄.

## 2. 사용자 회신 (합의된 것)

동의(*"맞는것 같아"*), 근거를 하나 더 — *"우리가 고친게 소비자에서 문제가 생겨서, 설계 결함이라 철회해야하는 경우는 릴리즈 하고 나서는 늦어. 그런 관점에서도 한번 방어해줄 곳이 진짜 필요하고, mock 이나 게이트만으론 안 되는 실제 관측을 크게 도와줘서 breaking 에 따라 두 킷을 고치는건 큰 비용으로 안 보이고"*. 조건 셋 동의. 덧붙임:

- **best practice를 보여 주는 데 힘쓸 것** — *"스킬도 쓰지만, 참고 자료로 우리 키트를 주고 자신 게임 자산들로 만들어진 ui키트를 만드려는 경우(본인들 만의 디자인 언어가 있는 경우) 같이 참고 자료로 넣어주면 이로운 방향이 되면 좋겠어. 구현을 힘 들이지 않고 착안해 올 수 있는 경로가 있거나, 팁을 얻을 수 있게"*.
- **M3 자산 라이선스**: 들어가는 서브 프로젝트에 라이선스 파일을, *"특히 . 을 뒤에 붙여서 더 서술해두는것으로"* (해석은 §3 — 사용자 확인 대기).

## 4. 1번 라이선스(했음)·2번 pesde 실측(sonnet 탐사, pesde 0.7.4, `target.environment = "luau"` 스크래치)

- 이름 문제(사용자): `quad@base` 꼴 별도 범위로 갈까, 그러면 개인 프로젝트 모양이 아니게 됨, 패키지 이름에 `/`를 더 못 넣음. 메인 의견: `qwreey/` 유지 + 이름 앞 `quad_kit_`을 묶음 표시로, 범위 이동은 하더라도 4.0 같은 끊김에 맞춤, `@`는 문서에서 부르는 이름으로만(실제 폴더 `kits/roblox-devui`).
- 1번: 두 킷에 `LICENSE`(MIT)·`NOTICE.md`가 이미 있었다. material에 `LICENSE.material-icons`(범위 서술 + Apache 2.0 원문, apache.org sha256 cfc7749b…), devui NOTICE에 기본 아이콘 id가 Iris 자산이라는 고지(빠져 있던 것).
- 2번 실측: 중첩 워크스페이스는 **안 됨**(안쪽 `workspace_members`가 무시되고 안쪽 멤버가 설치되지 않음). 루트에 **글롭 `kits/*`는 됨** — 글롭 멤버가 루트 멤버를 `workspace =` 의존으로 받고 멤버 폴더에서 install해도 성공. 이름 규칙: 범위·이름 모두 소문자·숫자·밑줄만, 범위 3~32자·이름 1~32자, 밑줄로 시작·끝 금지, 숫자만인 이름 금지 — `qwreey/quad_kit_devui`·`quad/base` 허용, 하이픈 거부. 범위 소유: 미확인(로그인이 GitHub 기기 코드 흐름이고 서버가 범위별 게시 권한을 판정한다는 정황까지만).
