## 1. 지시와 설계

사용자(compact 직후): *"다음 감사: 문제가 회귀되어 다시 발생했거나, 변경으로 인해 발견된것 등을 찾아보자. sonnet 이나
opus 모델을 사용해 하위 에이전트로 굴리고, fable 은 쓰지 않아도 될것 같아. 결과를 네가 받아 검증하는걸 하고, 여러
서브에이전트를 굴려도 좋아."* 그 전 메시지에서 예고한 각도는 "누적 변경으로 다시 생긴 문제 + 에이전트가 archive에서
못 본 근거로 잘못 처리된 것".

각도 다섯을 한 메시지에 병렬로 띄웠다(사용자 허용 — 평상시 "한 턴 하나" 규약의 예외). 코드 추적 넷은 opus, 문서 정합은
`quad-doc-auditor`(sonnet). 공통 프롬프트: 읽기 전용(파일 생성·수정 금지, `git stash`/checkout 금지, test.sh·relink·gen-d
emit·Studio MCP 금지), 원장 위치(archive `v2-initial-implementation/` = 후속 에이전트가 못 본 자리라는 힌트), 오늘 실제로 난
`H-480`→`H-38`→`H-485` 사례를 "이런 종류를 더 찾아라"의 본보기로, 마지막 메시지 하나에 전부·미완 표시·후속 약속 금지.
- A(opus) Slot/Bookkeeping vs 옛 계약(`H-38`·`H-240`/`H-113`/`H-124`·`H-385`·`H-479`~`H-483`, spec 6절 커버리지)
- B(opus) Dispatch/Modifier vs 옛 계약(`H-214`/`H-228`·`H-52`·`H-250`·`H-482`·`H-484` 선언 열둘 정확성)

## 2. 도착 순서와 검증

E(5분) → B(9분) → A(12분) → C(12분) → D(13분). 토큰은 17만~26만씩.

- **E 다섯**: 전부 grep으로 실재 확인, 같은 부류 둘(`question.md`·`external-review-entry.md`)을 메인이 추가로 잡음. 즉시
  반영(`H-489`).
- **B-1/A-1 (같은 발견)**: 원장 문장의 언어 계약 절반(삽입 UB)이 틀린 건 확실. 도달성은 메인이 `Observer._receive`
  (`_running` save/restore, `H-332`)와 `State.emitDown`(동기)을 읽어 확인 — 재진입 reconcile은 실재. 그러나 `slot-plan.md`
  "재진입성" 절이 그 재진입을 UB(provider 버그)로 못박았고, 옛 코드도 재진입 뒤 바깥 루프가 낡은 `keys`/`seen`으로 돌아
  의미론은 이미 깨져 있었다 → clone 복원 안 함, 원장 정정 + 주석(`H-486`). 감사자 심각도 MED → 메인 판정 "논거 오류(문서)".
- **A-2 (Clear 창 안 raise → 동결)**: `rawSplice`도 창 안에서 `rawUnmount`·`nativeExtract`를 돌리고, List KeyGone 패스는 창
  안에서 파괴까지 한다(round7 `H-485`가 "그 List는 어차피 죽는다"로 수용) → 새 부류 아님. 다만 `H-479` 전엔 Slot이 살아
  있었다는 심각도 상승은 사실 → Q40으로 올림(권고 (a) 그대로 + 정본 한 줄; (b) 파괴를 창 밖으로 열 줄 패치도 제시).
- **A-3 (None 분기 되감기 커버리지 0)**: 확실. 처음엔 10절처럼 길이 Compute 안에서 `setLength`를 부르는 구성을 생각했으나,
  `H-445`가 검사 `len:Get()`을 Observer 콜백(창 밖)으로 옮긴 뒤로는 Compute가 recompute 전에 이미 캐시돼 contribution 창에서
  사용자 코드가 돌지 않는다(10절은 지금 그 경로가 아니라 setLength 재귀로 통과한다 — 단언은 여전히 참). 그래서 5절 모양(뒤
  Source의 Observer에서 `setLength`)으로 커서를 정확히 None 자리 2로 내리는 14절을 짰다. 첫 실행에 통과, test.sh exit 0.
- **C 여덟**: 결정 역전 0. 반영 누락 셋(C-1 `claim-plan`, C-2 `slot-plan` 의사코드 둘, C-5 `IndexOf` O(n))과 원장 표시

- **D 셋**: 동작 회귀 0(2160줄 대조). 주석 잔재 셋 실재 → `H-490`. B-3(`listHandlers` 주석)도 같이.

## 3. 판단 메모

- 감사자 심각도는 입력이지 결론이 아니다 — A-1 MED·A-2 "새 실패 모드"는 옛 결정 범주(UB로 수용된 재진입/창 안 던짐)와
  대조하면 낮아진다. 반대로 E의 LOW 포인터 하나(`external-review-entry.md`)는 외부 모델의 첫 진입점이라 실질 영향이 컸다.
- 병렬 다섯이 이번엔 유효했다: A·B가 같은 발견을 독립적으로 내 교차 확인이 됐고, C·D·E는 겹치지 않았다. 다만 이건 사용자가
  비용을 허용한 구간이라 가능했던 것 — 기본 규약(한 턴 하나)은 그대로.
- `H-445`의 부수 효과(10절이 contribution 창을 더 이상 안 밟는다)는 이번에 발견했지만 단언이 참이고 14절이 되감기 경로를
  덮으므로 따로 항목을 만들지 않았다 — 필요해지면 10절 헤더 정정.
