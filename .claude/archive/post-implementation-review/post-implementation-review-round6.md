## 2. 기각 및 철회된 항목과 상세 사유 (Rejected Proposals)

### ❌ [기각 1] Luau 사용자 정의 타입 가드 (`x is Type`)
- **원안**: `quad.isState(x)` 등의 반환 타입을 `x is State<any>`로 선언하여 유저 코드에서 캐스팅(`:: any`)을 제거하자.
- **기각 사유 (팩트체크 오류)**:
  - Luau 공식 스펙상 TypeScript 스타일의 사용자 정의 타입 술어(`x is Type`) 문법 자체가 **존재하지 않습니다**.
  - Luau는 `type()`, `typeof()`, 그리고 테이블의 프로퍼티 존재 여부를 통한 **빌트인 타입 정제(Type Refinements)**만 지원합니다.
  - 현재 `quad`가 이미 구축해 둔 마커 프로퍼티(`__quadTag: true`, `__quadState: true` 등) 기반의 정제 방식이 Luau 타입 체커의 설계 철학에 가장 완벽히 부합하는 정석적인 구조입니다.

### ❌ [기각 2] `Slot:List` Reconcile 전역 스크래치 테이블 재사용 (GC Churn 최적화)
- **원안**: `reconcile` 실행 시마다 생성되는 `seen = {}` 등의 해시 테이블을 모듈 레벨 스크래치 버퍼로 두고 `table.clear`로 재사용하자.
- **기각 사유 (재진입 결함 및 부작용 발생)**:
  - `reconcile` 루프 내부에서 호출되는 `updateFn(item, ...)`은 **임의의 사용자 코드**입니다.
  - 사용자의 `updateFn` 실행 도중 다른 State가 갱신되거나 슬롯에 대한 추가 조작이 일어날 경우, 동일한 리콘실 클로저나 상위/하위 슬롯으로 **재진입(Re-entrancy)**이 발생할 수 있습니다.
  - 만약 모듈 스코프의 단일 스크래치 테이블을 공유한다면, 재진입 시점의 실행이 상위 실행의 `seen` 테이블을 오염·초기화시켜 심각한 슬롯 상태 불일치(State Corruption)를 초래합니다.
  - 따라서 매 `reconcile` 주기마다 독립적인 로컬 테이블을 생성하는 현행 방식이 안전성과 격리를 보장하는 필수적인 설계입니다.

### ❌ [기각 3] ErrUtil의 자동 클래스/메서드 탐색 태깅 (List Drift 방지)
- **원안**: `Impl` 테이블을 export할 때 모든 함수를 자동으로 순회하여 `SURFACE` 에러 레벨을 태깅하도록 하자.
- **기각 사유 (불필요한 과도한 결합도)**:
  - `ErrUtil`(`quad-error`)은 에러 스택 블레임 레벨만 추적하는 완전히 분리된 초소형 독립 유틸리티입니다.
  - 에러 유틸리티가 각 모듈 내부 구현체(`Impl`)의 구조나 객체 지향적 컨벤션을 알도록 결합하는 것은 아키텍처 층위를 오염시키는 불필요한 엔지니어링입니다.

### ❌ [기각 4] 반응성 DAG 무작위 속성 기반 퍼징(Fuzzing) 하네스
- **원안**: 무작위 DAG 토폴로지를 생성하여 글리치 프리(Glitch-freedom)를 검증하는 거대한 속성 기반 테스트 프레임워크를 도입하자.
- **기각 사유 (프로젝트 범위 이탈 및 '단순성' 철학 위배)**:
  - `quad`의 설계 철학은 **"단순성(Simplicity)의 유지"**입니다.
  - 에포크 추적, emit 전파, 게이팅, 컴퓨트 노드 등 파이프라인의 각 단위는 극단적으로 단순하게 설계되어 있으며, 그 작은 요소들이 결합하여 전체 렌더러를 형성합니다.
  - 이를 강화하겠다는 명목으로 거대한 퍼징 엔진을 구축하는 것은 프로젝트의 본질적인 범위를 크게 벗어나는 오버엔지니어링입니다.
  - 현재 구비된 49개의 결정론적(deterministic) 스펙과 실측 스크래치 하네스로도 상태 천이의 무결성은 이미 충분히 검증되고 있습니다.

## 3. 채택 및 반영 권고 항목 (Actionable Proposals)

인간 개발자의 검토를 통과하여 메인 에이전트(Claude)에 인계 가능한 실질적 개선안 3건입니다.

### 💡 [권고 1] 1급 프리미티브 `__tostring` 메타메서드 구현 (Good to have, DX 대폭 향상)
- **대상**: `Slot`, `Modifier`, `State`, `Source`, `Tag`, `Ref`
- **배경**: Studio 콘솔에서 `print()` 시 `table: 0x5a3f...` 대신 직관적인 상태 확인이 필요함.
- **구현 내용**:
  - `Tag`: `Tag("Rounded", "Primary")`
  - `Source`: `Source(v=42, rev=1)`
  - `State`: `State(cached=..., target=...)`
  - `Slot`: `Slot(len=3, mounted=true)`
  - `Modifier`: `Modifier(Frame, fields=3)`
  - `Ref`: `Ref(inst)`
- **평가**: 연산 핫패스 오버헤드가 전혀 없으며, 개발자가 출력 창을 통해 상태를 즉시 파악할 수 있어 DX 개선 효과가 매우 높음.

### 💡 [권고 2] `Err.setFuncLevel(level, ...fns)` 가변인자 지원 (경량 보일러플레이트 제거)
- **대상**: `quad-error` 및 각 모듈의 태깅 루프
- **배경**: 현재 파일 하단마다 `for _, fn in { ... } do Err.setFuncLevel(fn, SURFACE) end` 루프가 반복됨.
- **구현 내용**:
  ```luau
  -- 제안하는 가변인자 호출 형태
  Err.setFuncLevel(SURFACE, Impl.Get, Impl.With, Impl.Compute, Impl.Gate, Impl.Observer, Impl.Apply)
  ```
- **평가**: `ErrUtil`의 독립성을 훼손하지 않으면서도 수동 배열 생성 및 `for` 루프 보일러플레이트를 한 줄로 깔끔하게 축소 가능.

### 💡 [권고 3] 에러 메시지 포맷 정규화 헬퍼 (경량 포맷팅 지원)
- **대상**: `quad-error`
- **배경**: 모듈별로 접두어(`Slot:Get:`, `quad.Dispatch.getBlocker:`, `State: dep #1`)가 조금씩 상이함.
- **구현 내용**:
  - `ErrUtil` 내부에 모듈명, 메서드명, 실패 원인, `(got <type>)` 접미사를 일관되게 조립해 주는 초경량 문자열 포맷 헬퍼 도입.
  - 예: `Err.format("Slot:Get", "index must be a number", typeof(index))` → `"Slot:Get: index must be a number (got nil)"`
- **평가**: 일관된 진단 형식을 확립하여, 향후 외부 툴링이나 Roblox Studio 플러그인에서 에러 유형을 정규식으로 자동 그룹화·식별하기 용이해짐.
