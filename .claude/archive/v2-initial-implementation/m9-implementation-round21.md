## §4 배치 회신 대기 (② 갈래)

**[2026-09-06 회신 — 둘 다 사용자 숙고로 보류]**
- **Q2**: *"컴포넌트 경계에 함수 인자는 유저가 마음대로 둘 수 있는 부분이라 … 우리가 뭔가 강제하는 부분은 아니지 않아? … 일반적인 modifier를 위해서 그걸 flatten을 돕는 도구라던가(순수 슈거) 하는 방법을 생각하기는 했었음. 더 생각해보고 싶어."* → 이름은 강제 표면이 아니라 관례. 가칭 유지, 확정은 사용자 숙고 뒤.
- **`H-340`**: *"처음부터 커스텀 modifier는 peek를 통해서 하나하나 확인하는게 일반적이지 않을까? 그걸 돕는 슈거를 만드는게 나을 수도 … `Without`을 제공할 이유가 충분하다 생각해?"* → 에이전트 답(원문은 이 세션 대화): `Peek`로 커스텀 옵션을 읽는 게 1차 도구라는 데 동의. `Without`의 유일한 존재 이유는 "커스텀 키를 뺀 **나머지**를 부모 클래스 루트로 넘기는 것"인데, 사용자가 언급한 **flatten 슈거**(modifier를 평탄화한 plain 테이블로 받아 컴포넌트가 if/then/else로 고르고 나머지를 `D.Modifier.<Parent>()`로 다시 싸는 것)가 그 자리를 더 일반적으로 덮는다 — Modifier에 새 연산을 얹지 않고 경계에서 modifier를 **데이터**로 다루는 쪽. 그래서 `Without` 신설은 권고 철회, flatten 슈거와 함께 숙고 대상.

**[2026-09-06 후속 — 사용자 결정]** *"flatten 슈거 그거는 사실 추후에 개발되어도 되는 부분이고, 지금 개발하는데 결정이 막을 만한 요소도 아님. 그냥 백로깅 대상"* → Q2·`H-340` 둘 다 **백로그** `research/component-flatten-sugar-plan.md`(스캐폴딩 계획, 사용자 답 대기)로 이관. **열린 문항 0, 확인 항목 0.**
