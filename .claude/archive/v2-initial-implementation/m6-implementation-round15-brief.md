## §2 가드 — 메인 규약과 다른 지점 (전부 사용자 승인 사항)

1. **라이브 문서 불가침**: `.claude/base/`·`ROADMAP.md`·인덱스 3층 등을
   **수정하지 않는다**. 쓸 수 있는 곳은 코드(`quad-base/src`·`test`)와
   자기 산출 문서 둘(`m6-implementation-round15.md`,
   `session/YYYY-MM-DD-NN-*.md`)뿐. 문서 반영은 메인의 통합 몫 —
   핸드오버 워크플로 폐기(에이전트 67개)의 교훈.
2. **② 갈래는 잠정 구현으로 밀지 않는다 — 멈춰서 부른다**(사용자 정정
   2026-09-02: *"문제가 생기면 차라리 나를 부르는게 맞을수도 … 나비효과로
   잘못된 부분을 먼저 못 보고 에이전트가 크게 헛발질 할 수 있거든. 이미
   개발자가 찾은 더 상위의 문제였던게 많아서, 멈추는건 필요해보여. 내가
   여럿 봐도 돼"*). 규칙: ② 발견은 원장에 문항+권고로 기록하고 코드엔
   `-- TODO(H6-n)` 마커만 — **그 결정에 의존하는 코드는 쓰지 않는다**
   (메인 규약 그대로). 독립 작업은 계속하되, **의존 작업이 막히거나 상위
   설계 문제 냄새(quad-base 코어 결함 의심, 정본 문서 간 모순, 나비효과
   위험)가 나면 즉시 작업을 멈추고** 쌓인 문항을 자기 채팅에 배치로 정리해
   **사용자 회신을 직접 기다린다** — 사용자가 fork 채팅에 직접 들어와
   답한다(사용자: *"나도 서브 에이전트 채팅 들어갈 수 있어"*). 회신을 받으면
   반영하고 계속. ③(대량 무효화 규모)은 언제나 즉시 중단 — 이때는 메인
   세션 몫까지 걸린 문제일 수 있으니 최종 보고로 복귀한다.
3. **번호 접두 `H6-`**: 위 명명. 메인/타 fork 원장과 절대 안 섞는다.
