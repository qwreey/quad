## A. UB 입력에 대응해 쌓인 가드 (가드를 뺀 사본으로 스펙 재실행 + CLI mock 벤치)

가드를 뺀 사본 넷(State 가드 제거, Bookkeeping 되감기 제거, Observer 설치 루프 제거, Slot Q52/Q74 끔)에서 깨진 스펙은 **전부 UB 장면을 고정한 절**이었고 정의된 경로를 고정한 절은 하나도 안 깨졌다.

- **State 사슬**(`H-85` 2026-08-25 → `H-198` 08-31 → Q50 09-17 → `H-540` → Q93/Q98 09-29): `H-85`·`H-198`은 "Compute 순수성"(09-07)보다 먼저 들어왔고 그 근거("재계산 중 상류 쓰기", "yield 사이 타이머 Set")가 뒤에 UB가 됐는데 메커니즘은 재검토되지 않았다. 항목: (1) `H-198` Get 재시작 루프 — UB 전용, 재계산하는 Get마다 `Refresh` 한 바퀴 더(핫 패스), 고정 스펙 `spec.state` 6·`spec.gate` 10 / (2) fn 직전 스탬프 위치 — 비용 0, 근거 문구만 / (3) Q50 `_computing` 세대 도장 — 순환(자기 읽기)·yield 감지, 빼면 순환이 내부 blame `stack overflow` / (4) `H-540` 드리프트 가지 — (3)의 던짐 뒤 도장 때문 / (5)(6) Q93·Q98 — yield 전용, 정의 경로 바이트 동일, `spec.state` 16 / (7) `H-85` 캐시 카운터 쌍 — 정의 경로와 공유, 유지. 전부 뺀 사본: 30단 체인 Set+Get −10~12%, 팬아웃 1000 −8%; State.luau 약 80줄.
- **Bookkeeping**: (8) `H-240` Get 창 검사 ①② + `getOffsetAt` 재시작 — 그 창에서 도는 사용자 코드는 길이 Compute의 fn뿐이라 UB 전용, **고정 스펙 없음**(뺀 사본 전부 통과), 사실상 죽은 방어 코드 / (9) `H-101`/`H-113`/`H-124` Set 창 되감기 + `offsetSetUpTo` 필드(쓰기 여덟·읽기 넷, 읽기는 전부 되감기 검사) — 커서가 내려가는 입력은 자기 Offset 되먹임(UB)과 "Offset Observer가 자기 자리를 Remove/Extract"(미정 경계 — 안 막으면 `Quad0024`로 owner 동결)뿐, 재계산 자리마다 5~9%, 고정 스펙 `spec.lengthoffset` 5·14 / (10) 재진입 게이트·상한 재읽기 — 커서 뒤쪽 CRUD는 정의된 경로, 유지.
- **Observer**: (11) 3′ 설치 루프(`runLoop`·`_pending`/`force`) — 동기 fn 도중 오는 배달은 fn 자신의 호출 트리(자기 Set 또는 깨운 남의 콜백)나 yield에서만 오므로 구조상 되먹임 전용; **루프를 빼고 "먼저 합류 + 보류 → 바인드 때 따라잡기"만 남긴 사본에서 `spec.slot` Q73 절은 통과**, 깨진 것은 `spec.observer` 1(일부)·10·13(install)·14(자기 Set·제3 Observer 경유 간접 되먹임); 비용 잡음 / (12) `H-332` `_running` 저장/복원 — 비용 0, `spec.observer` 9a / (13) `_receive` 인라인 중복(재귀 깊이 이유) / (14) `Quad0262` — (11)과 운명 같이 / (15) `_seenRevision` — 정의 경로와 공유, 유지.
- **Effect**: 지연 재실행·Q51·fn 전 Sync·생명주기 게이트는 정의 경로 전용 — 유지.
- **Slot**: Q52 `_materializing`·Q74 `raiseChain` — 사용자 결정(Q74는 회고 1차가 정상 경로 결함으로 판정). `H-486`(KeyGone 순회 `table.clone` 제거)이 좋은 선례.
- **뿌리 아님**: emitDown·Ref 스냅샷, Dispatch NOOP 소비, StoreBind `Quad0070`, `q.Out` 같은 값 건너뛰기, Property Tween "모으고→쓰고→부른다".

## B. 되먹임 허용의 결정 이력

사용자가 "자기 입력 되먹임 허용"을 원칙으로 세운 적은 없다. 사용자 원문이 직접 정의한 것은 셋 — Effect 지연 재실행(`H-60`, React 비유 — **유일한 실제 필요 주장**), Ref 콜백 재진입(`H-169`), Slot 되감기(`H-101` — 단 에이전트가 "실재하는 경로"라며 낸 버그에 대한 답) — 이고 셋 다 파동을 푸는 장치를 같이 설계했다. 사용자가 먼저 한 말은 UB 쪽: 2026-08-04 "방어 안 함 = provider 버그", 2026-08-11 recompute 도중 같은 Slot 길이 재쓰기를 UB로 명명(사용자 제안 — `H-101` 원장이 이것을 인용하지 않아 두 결정이 서로를 못 봄), 2026-08-21 *"옵져버가 Set을 불러 자신이 무한반복 되게 만드는거 UB아닌가요?"*. "지원"은 에이전트 서술이 쌓았다: `gate-plan.md` "유한한 재진입은 지원한다"(2026-08-21, 근거는 에이전트 자신의 08-14 의사코드 주석) → `H-101`이 그 문장을 근거로 UB 갈래 기각 → `H-240`의 비대칭 논거 → `H-332`(09-06 자율)·`H-709`(09-27 자율)가 Observer 자기 Set 재귀를 정의된 동작처럼 → 3′ 반영이 clamp 수렴을 spec 단언으로. 같은 `slot-plan.md` "재진입성" 문장을 round8(09-08)은 UB로, Q73(09-27)은 지원으로 읽었다. 3′ 사용자 원문 *"첫 발화든 어느 발화든 자기 state 가 set 된다면 다시 실행되어도 됨"*은 앞뒤(*"별 의도가 없던 부분"*, *"의도치 않게 막게 된것 같음"*)로 보아 갱신 유실 금지 규칙이지 자기 되먹임 허용이 아니라는 판정. 경계 사례: Gate/Debounce flush 중 하류가 상류를 Set(하류가 Observer면 UB 입력 — `spec.debounce` 10·10b·13, `spec.gate` 6이 정상처럼 고정), `q.Out`/`OnChange` 왕복은 정상 경로(엔진 무신호·같은 값 거름이 푸는 도구)라 Observer UB 문장에서 명시적으로 뺄 것. UB로 바꿀 때 고칠 문서·스펙 목록은 보고 원문(세션 대화) — base 여섯 자리·공개 문서 일곱·스펙 여섯 파일·코드 주석 셋.
