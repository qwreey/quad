# Naming review — devui (a developer UI kit for Roblox), 2 names

You are reviewing public API names for a UI kit. Judge them from the point of view of the kit's USERS (Roblox developers writing tool UIs). Everything you need is below — do not look for files. Reply in Korean, concisely: for each item, your pick, a ranked shortlist, and one or two reasons. Flag a name that would mislead.

## Context
- devui is a Dear ImGui / Iris-inspired developer UI kit for Roblox, built on a reactive library (quad). Retained mode: widgets are functions taking a props table; reactive values are `State<T>` (read-only) and `Source<T>` (writable). Inspired by ImGui/Iris, not bound to follow them.
- Widgets are called as `Devui.Window({ ... })`, `Devui.Button({ ... })`, `Devui.MenuBar({ Children = ... })`, `Devui.Menu({ ... })`.
- `Devui.MenuBar` already exists: a horizontal bar of `Menu`s (File / Edit / View …, ImGui `BeginMenuBar` / Iris `MenuBar`). Today an app puts it as the FIRST CHILD of a window's content — it then sits inside the window padding (gaps left / right / top), scrolls with the content, and the app subtracts its height by hand from the window's reported content size.
- Window props that set conventions: `Title`, `Icon: string?` (the image shown when the window is collapsed to an icon), `Children` (the content), flags `NoTitleBar`, `NoResize`, `NoMove`, `NoClose`, `NoCollapse`, `NoDock`; `AvailableSize: Source<Vector2>?` (an output: the content area's size); `Focused: Source<boolean>?`. Inner-element props use a prefix: `InputText.FieldModifier`, `FieldSpread` (the inner box), `SliderNum.TrackSpread`.
- Windows can be grouped as tabs and docked; each window keeps its own content.
- Button props today: `Text`, `OnClick`, `Disabled`, `Toggled` (the on-look of a toggle button), `Hooks` (e.g. a tooltip hook), `Style`, `Modifier`. `Style.Icons` holds built-in icon image ids (`Close`, `RightTriangle`, …).

## Names to judge
1. **Window's menu-bar slot.** A new Window prop: an element (usually `Devui.MenuBar({ ... })`) that the window draws right under its title bar, OUTSIDE the window padding, full width, not scrolling with the content; the window measures its height and removes it from the content area and `AvailableSize`. When windows are tabbed together, the selected window's bar shows. Proposed: `MenuBar`. The user's worry: `MenuBar` is also the widget name, so `Devui.Window({ MenuBar = Devui.MenuBar({ ... }) })` may read oddly, or the slot may look like it only takes a MenuBar (any element should fit — a toolbar row of icon buttons is likely too). Alternatives to judge: `MenuBar`, `Header`, `TopBar`, `Toolbar`, `HeaderBar`, `Bar`. Also judge: should the WIDGET be renamed/aliased (e.g. `WindowMenuBar`) to show it belongs in that slot, or should the widget stay generic ("placeable anywhere, designed for that slot")?
2. **Button image.** A new Button prop: an image id (`string | State<string>`) drawn inside the button with padding around it; with `Text` it shows icon + text, without `Text` an icon-only square button. Proposed: `Icon`. Alternatives: `Image`, `IconImage`. Note the Window prop `Icon` already exists with a different role (the collapsed-window image).
