## (ii) 발견 문단

**Quad0037 — 이미 채운 값을 지우려는 경우(불충분).** 페이지 01-core-reactive.md:47의 고치려면은 "지우려는 의도라면 `:Set`을 아예 부르지 마세요"다. 가방이 새것일 때는 맞지만(케이스 a, `Peek=nil`), 사용자가 `nil`을 넘기는 흔한 동기는 **이미 `:Set`한 값을 지우려는** 것이다. 그 경우 `:Set`을 부르지 않으면 값이 그대로 남는다 — `A.luau:80~88`, 출력 `FIX=intent-fail after not calling :Set, Peek=dark`. 가방에는 제거 API가 없고, 레퍼런스 sugar/01-context.md:89가 이미 "만드는 쪽이 `q.Context()`로 새 가방을 만들어 필요한 키만 다시 `:Set`"을 길로 적어 두었다. 문구 대안: "이미 넣은 값은 지울 수 없습니다 — 그 키 없이 새 `q.Context()`를 만들어 필요한 키만 `:Set`하세요"를 한 줄 덧붙이기.

**Quad0044 — "새 Ref를 만들거나"의 공유 팩토리 경우(불충분 후보).** 페이지 01:103은 "새 `Ref`를 만들거나, `Handle`을 빼고 팩토리의 `:Flush()`/`:Cancel()`을 쓰세요"다. 에러의 전형 경로는 sugar/03:146이 적듯 "팩토리를 재사용하며 같은 Handle을 쓰는 경우"인데, `Handle`은 팩토리 **옵션**이라 같은 팩토리의 두 번째 `:Apply`에 새 Ref를 넘길 공개 경로가 없다. 새 Ref가 효과를 보려면 새 Ref로 **팩토리도 새로** 만들어야 한다(`A.luau:185~198`, `FIX=ok a=2 b=1`). 글자 그대로 "팩토리는 그대로 두고 새 Ref"를 하려면 사용자가 들고 있는 옵션 테이블을 고쳐 쓰는 수밖에 없는데, 그게 동작하는 것은 팩토리가 `opts`를 참조로 들고 있어서일 뿐 문서화된 길이 아니다(`A.luau:643~654`, `FIX=ok opts-alias route filled r2=true`). 문구 대안: "새 `Ref`로 팩토리를 `:Apply`마다 새로 만드세요(`Handle`은 팩토리 옵션이라 팩토리 하나에 Ref 하나)". 이 옵션 테이블 별칭 동작 자체는 E28이 0039에 대해 적은 "`_opts` 참조" 관찰과 같은 뿌리다.

**Quad0184 — 자기 값 읽기의 의도(문구 보강 후보, 판정은 정확).** 페이지 01:263은 "계산 함수가 자기 자신을 순환 참조하지 않게 하고"만 말한다. 자기 값을 읽는 흔한 의도(누적·직전 값 비교)는 `:Compute` 콜백의 두 번째 인자 `previous`로 그대로 풀린다(`A.luau:441~447`, `FIX=ok a=1 b=3`). 고치려면이 이 인자를 가리키지 않으므로, 한 구절("직전 결과가 필요하면 두 번째 인자 `previous`를 쓰세요") 보강 후보. yield(b)·던진 뒤 재읽기(c) 갈래는 글자 그대로 동작한다(c는 상류 `:Set` 뒤 `Get=5`).

**Quad0124 — 회복 전 재읽기의 id가 바뀜(E28 기추적, 현재 문구에 남아 있음).** 페이지 01:191 "보통은 경계가 다음 세대에 돌아오면 회복됩니다"는 실측으로 맞다(`A.luau:347~354`, hi를 움직이자 `v=20`). 다만 경계가 돌아오기 전에 한 번 더 읽으면 0124가 아니라 Quad0184가 난다(`A.luau:656~661`, 출력 `TRIG=miss … Quad0184 State: Compute fn is already running …`). "계속 나면"이라는 문구를 믿은 사용자는 두 번째부터 다른 번호를 본다. 0184 페이지 "언제"의 "직전 계산이 던진 뒤 같은 세대" 갈래가 이를 덮으므로 동작 문제는 아니고, 0124 고치려면에 "회복 전 재읽기는 Quad0184로 보입니다" 한 줄이 후보.

**Quad0123 — blame이 quad 내부(E28 기추적, 현재도 남음).** `q.Tag("A"):Apply(q.Operator.Not)`는 `quad_base/src/Tag.luau:195`, `q.Modifier():Apply(q.Operator.Bnot)`는 `quad_base/src/Dispatch/Modifier/init.luau:189`로 blame이 떨어진다(`out/A.txt` 해당 줄). 페이지 01:182 "언제"는 두 경로를 이미 적었지만 blame은 말하지 않는다. 직접 호출 `q.Operator.Not(5)`는 사용자 줄(`A.luau:324`)로 간다. 고치려면("`state:Apply(...)`로만 붙이세요")은 직접 호출 갈래에서 정확하고, Tag/Modifier 갈래는 원래 의도(Tag 부정 등)가 State 없이 성립하지 않아 판정 대상 아님.

**Quad0192 — 미도달.** 유일한 호출자가 Source 설치이고 그 설치가 바로 앞에서 State를 설치한다(E28). 공개 API로 닿는 경로를 찾지 못했다. 페이지 고치려면은 "(문서 미정)".

**blame 이상(위 0123 외) 없음.** 나머지 전부 케이스 파일 줄로 떨어졌다. 0039는 신호 시점 검사라 blame이 상류 `src:Set` 줄(`A.luau:121`)이다 — 페이지는 "신호가 들어오는 시점에 읽어 검사"라고 말할 뿐 blame 줄은 말하지 않으며, 그 서술과 모순은 없다.

**누락 변형(E28 목록 밖)** — 새로 찾은 것 없음. 0044의 옵션 테이블 별칭 경로는 E28의 0039 `_opts` 관찰과 같은 뿌리라 새 변형으로 세지 않았다.
