지금은 quad 라는 roblox 엔진에서 작동하는 ui 렌더러를 재구현할 목적에 있어. quad 문서는 https://quad.qwreey.kr/ 여기 있고 소스는 https://github.com/qwreey/quad 이거임

이 쿼드의 특성에 대해 문서랑 레포 보고 파악해보자. 레포는 클론해뒀어. quad 폴더 보면 됨.

그거 이외에 fusion 이라는 녀석과 vide 라는게 존재함. 이것도 클론해 두었는데 비슷하게 roblox 엔진에서의 렌더링 라이브러리야. 비슷하면서도 서로 많이 다른 성격을 가져. 필요하다면 해당 라이브러리에 대해 검색해도 좋아.

지금 내 생각들은 아주 러프하게 raw-userinput.md 에 있어. 리팩터링에 반영하고 싶은 생각들임.

이 프로젝트는 기본적으로 .claude 폴더 안에 qa-request, base, archive, feedback, research 를 만들고 그 안에 plan 들을 적절히 배치하가며 만들고, 너가 할 TODO 를 적당히 CLAUDE.md 에 배치하가며 수행해야해. 루프를 써서 사용자의 질문이 필요 없는 작업은 싹 수행되도록 만들어야해. 사용자는 깨어 있을 때 플랜들에 대해서 많은 기술 자문을 도와줄꺼야 - 사용자는 lua 에 대해서, roblox 엔진에 대해서 오래 깊게 배운 사람이야. 많약 크리티컬한 결정이 필요하면 위임하고 plan 을 연기해. 사유들을 아래 적어서 나중에 유저가 질문을 달라 할 때 질문을 하고 해결해 나가야함.

컨텍스트 부패에 꼭 주의해. 리서치가 코드를 엄청 읽고 길어질것 같다면 리서치에 난이도에 따라 sonnet 이나 더 낮은 모델에 위임해. 찾아야 할것을 찾고 정리하도록 시켜.

코드 디자인과 클로드 폴더 디자인을 실제 예를 보기 위해 내 프로젝트 몇개를 클론 더 해뒀어.

rbvm 은 roblox 엔진 객체에 라이프사이클을 깊게 연관시키는 작업을 수행하는 방식을 거의 완벽히 구현해내. 로블록스 엔진 객체 라이프사이클과 register 의 연결은 어떻게 보존할지 이걸 보고 확인해봐.

tbox 는 프로젝트 디자인과 루아우의 타입 기능들을 많이 보여주는 예야. 이걸 보고 타입이나 프로젝트 구조를 어떻게 잡을지 생각해봐.

루아우의 기본 기능들은 https://roblox.github.io/luau/syntax.html 여기서 찾아볼 수 있어.

중요한 점은 이건 너만 알고 끝난다가 아니야. 모델이 clear 되어가며 handoff 될 수 있도록 적절한 자기 문서화가 꼭 필요해. 나중에 재작업이 생기지 않게 작업한걸 완료로 만들고, 작업 더 해야할걸 적고, 해나가야해. 이게 어느정도 성공한 프로젝트가 있어. code-docker 야. 그 안에서 특히 webmanager 폴더의 .claude 를 봐. 잘 메니징 된 plan 방식의 특징을 확인할 수 있어.

작업 효율을 위해 적절히 에이전트로 병렬 작업을 수행하는것도 하도록 해. 이제 quad 재작성에 대한 계획을 만들고 에이전트로 사용자가 깨어있을 땐 대답해주고, 사용자가 잘 땐 직접 개발하는걸 하면 돼. 여기에 대해 사용자가 루프를 설정해야하거나 할 일이 있으면 프로젝트 루트의 HUMAN_TODO.md 에 알려주면 됨.

또, roblox 에 mcp 로 연결해 너가 테스트 할 수 있게 만드는 방법이 있다거나 하면 알려줘. 연결을 해줄게. 단 roblox studio 는 잘 죽는 편이야. 이게 죽었을 때 살리려고 위험하게 명령을 실행하거나 많은 시도를 하려 하진 말아야해. 그 날엔 테스트 없이 할 수 있는걸 하거나 대기해.

작업 기간은 길게 잡고 있어. - 재작성의 이유는 코드 퀄리티와 지속 가능성이야. 이건 개별 프로덕트라기 보다 '라이브러리' 라는 점을 기억해. 빠른 이터레이션 보다 정확성과 코드 퀄리티가 중요할것이야.
