# 에러 식별자(에러 ID) — 번호 공간을 어떻게 나누고, 어디에 붙이고, 무엇을 약속할지

**상태**: base — **[2026-09-22 사용자 결정, 같은 날 착수]** 7절 문항 다섯 전부 권고대로 확정(연구 원문은 아래 그대로 — 갈래 서술은
결정 전 시점). 결정 요약: **(C) 평평한 순번 `QuadNNNN`**(4자리, 번호에 뜻 없음) / **접두**(사용자: *"뒤에 두면 ... 으로 짤려서 사라짐"*) /
**문서 페이지가 곧 레지스트리**(`docs/reference/errors/`, `### QuadNNNN` 절) / **ID는 안정 계약 — 재사용 안 함, 분기 허용**(사용자:
*"재사용 안 함. 권고대로"*) / **222곳 한 번에**, 작은 에이전트를 직렬로 오래(사용자: *"작은 에이전트를 오래 써도 좋아. 시간은 많으니,
토큰을 너무 한번에 쓰지만 말고, 작게 오래 도는걸 추천해"*). 게이트는 `scripts/error-codes.py`(규칙은 그 docstring이 소스: 리터럴
접두 / `"QuadNNNN " ..` 연결 / `-- error-code: <이유>` 주석 셋 중 하나, 소스 전체 유일, 문서 절 필수), 롤아웃은 결정론적 배정 계획
(정렬된 파일·줄 순 → `Quad0001`부터; 한 자리가 메시지 둘을 내면 둘째는 `--next`)을 다섯 배치로. 사이드바 "Errors (에러 코드)" 그룹.

**계기**: docs-review 2-3(how-to 09 부록의 "에러 문구 → 레퍼런스 앵커 색인 표")을 닫으며 사용자가 방향을 세웠다 —
*"에러 문구: 보통 일반적으로 Quad10000 식으로 에러 아이디 스페이스를 가지는게 좋다고 보는데, 이 숫자를 어떻게 할당할 지 확인해볼
필요가 있는듯. 앞 어디 까지는 카테고리, 뒤는 그 안에서 나는 에러 이렇게 두고 수를 할당한다던가 하는 부분을 슬슬 결정해야할것 같아.
그래야지 에러 문구에 대하여 검색하고, 거기에 대한 설명이 있는 에러 설명 페이지를 만들어 낸다던가 할 수 있을것 같아. … 색인표는
에러 문구가 API가 아니라는 결정 - 자체는 그걸 해소하기 위해 에러 태깅-id 화를 수행하려 했던 기억이 있음."* 그 기억은 맞다 —
`ROADMAP.md` 백로그 2026-09-15 항목(공개 표면 (11) (ii): *"문서에 grep 할 수 있는 표면이 없다는건 아쉽게 느껴져 … 앵커가 있어야한다는
점은 여전히 필요"*)이 이 문서의 착수 지시다.

## 1. 지금 상태 (사실)

- **raise 자리 222곳**(`quad-base/src`·`quad-roblox/src`의 `errorBefore`/`errorBeforeNearest` 호출). 메시지는 `주어: 이유 (got X)` 한 모양의
  **리터럴**로 raise 줄에 통째로 있다 — 사용자 결정(2026-09-08, `architecture.md` "메시지 모양"): 포맷 헬퍼 없이 소스 grep으로 메시지 → 자리를
  찾을 수 있어야 한다.
- **메시지는 API가 아니다**(공개 표면 (11) (i), 2026-09-15) — 문구로 분기하지 말라는 정책 한 줄이 레퍼런스·extend에 있다. 그래서 문구가
  바뀌는 것은 비파괴이고, 문구에 무언가를 **덧붙이는** 것도 비파괴다.
- **던지는 값의 모양**: `quad-error`의 `errorBefore(content, level)`는 `error(content, level)`을 부른다. `content`가 문자열이면 Luau가
  `파일:줄: ` 접두를 붙이고(blame이 사용자 줄을 가리키도록 level을 계산하는 것이 이 패키지의 일), `Fallback`/`Traceback`의 `err: any`는
  그 문자열을 가공하지 않고 넘긴다(sugar/05).
- **문서 쪽**: 레퍼런스 페이지마다 "에러" 표가 문구를 그대로 싣고, how-to 09가 함정별 문구를 인용한다. 문구가 바뀌면 표가 낡는다 —
  `doc-check`는 문구 일치를 검사하지 않는다(2026-09-14 감사 루프가 손으로 전수 대조했다).

## 2. 목표

1. **검색 표면**: 에러를 본 사람이 식별자 하나로 문서·이슈·소스를 찾는다(문구가 바뀌어도).
2. **설명 페이지**: 식별자마다 "무엇이 잘못됐고 어떻게 고치나"가 있는 자리 — 레퍼런스의 에러 표를 대체하거나 그 표가 가리키는 앵커.
3. **비파괴**: 메시지는 여전히 API가 아니다. 식별자를 붙이는 것은 덧붙임이라 3.x 안에서 가능.
4. **관리 비용이 낮을 것**(사용자: *"메니징을 어떻게 미려하게 할 수 있냐가 큰 문제"*): 번호가 겹치지 않고, 문서 앵커가 깨지면 게이트가 잡고,
   새 raise를 추가할 때 손이 한 번만 간다.

## 3. 남들은 어떻게 하나 (사실 — 각 도구의 공개 문서 기준)

| 도구 | 모양 | 번호에 뜻이 있나 | 설명 페이지 |
|---|---|---|---|
| Rust `rustc` | `error[E0308]: mismatched types` | **없음** — 순차 할당, 폐기된 번호는 재사용 안 함 | `rustc --explain E0308`, 번호마다 마크다운 한 장(코드베이스에 동봉, 게이트로 존재 검사) |
| TypeScript | `error TS2322: Type … is not assignable` | 느슨한 영역(1xxx 문법·2xxx 의미…)이 있으나 규약으로 관리되진 않음 — 사실상 순차 | 공식 페이지 없음, 커뮤니티 색인 |
| MSVC | `C2065`, `LNK2019` | 접두 글자가 도구(컴파일러/링커), 숫자는 순차 | 번호마다 문서 페이지 |
| ESLint | `no-unused-vars`(문자열 규칙 이름) | 이름 자체가 뜻 | 규칙마다 페이지 |
| Luau / Python | 없음(문구뿐) | — | — |

공통점: **뜻은 이름·문서에 두고 번호는 유일성만 책임진다.** 번호에 카테고리를 심은 곳(TypeScript 초기)은 영역이 늘고 코드가 옮겨 다니면서
규약이 흐려졌다.

## 4. 갈래 — 번호 공간의 모양

- **(A) 카테고리 밴드 숫자** `Quad1203` — 천 자리가 영역(1 반응형 코어·2 디스패치/부기·3 Slot·4 Tag/Attr·5 Ref/Effect/Observer·6 quad-roblox
  핸들러·7 Declaration/Claim·8 슈거·9 백엔드 계약 …), 뒤 세 자리가 그 안의 순번. **장점**: 번호만 봐도 어느 층인지 보인다. **단점**: 이 코퍼스는
  소스 배치를 이미 두 번 재편했다(2026-09-07 패밀리 폴더, `Tween`의 quad-roblox 이동) — 코드가 층을 옮기면 번호가 거짓말을 하거나 재번호가
  필요하고, 재번호는 문서·이슈·사용자 코드의 검색 표면을 깬다. 밴드 소진(한 영역 999개)은 실질 문제는 아니다.
- **(B) 문자열 카테고리 + 순번** `Q-SLOT-012` — 읽기 좋고 grep이 잘 된다. **단점**: 메시지의 **주어**(`Slot:List:`)가 이미 같은 정보를 사람이
  읽는 형태로 담고 있어 이중이고, 주어가 바뀌면((A)와 같은 이유) ID도 흔들린다.
- **(C) 평평한 순번 + 레지스트리** `Quad0042` — 번호는 유일성만, 카테고리·주어·문서 앵커는 **레지스트리 파일**(한 곳)의 메타데이터. Rust 방식.
  **장점**: 코드가 어디로 옮겨 가도 번호 불변, 할당은 "다음 번호"라 충돌이 없고, 설명 페이지는 레지스트리에서 생성·검사할 수 있다.
  **단점**: 번호만으론 층을 모른다 — 그러나 메시지 주어가 그 역할을 이미 한다(`Quad0042 Slot:List: duplicate key …`).
- **(D) 번호 없이 주어를 앵커로** — 같은 주어에 메시지가 여럿이라(예: `Slot:List:` 아홉 곳) 앵커가 안 된다. 기각.

**메인 권고: (C).** 사용자가 떠올린 "앞은 카테고리, 뒤는 순번"의 실익(어느 층인지 한눈에)은 메시지 주어가 이미 주고 있고, 번호에 두 번째
분류를 심으면 그 분류가 코드 이동과 함께 낡는다. 카테고리는 레지스트리와 설명 페이지의 **묶음**으로 두면 사람에게는 같은 효과가 난다
(페이지는 층별로 묶여 있고, 번호는 그 안에서 뛰어도 된다). (A)를 고르시면 밴드 표를 이 문서 5절에 확정하고, "층 이동 시 번호는 안 바꾼다
(밴드는 첫 할당 시점의 층)"를 같이 못 박아야 재번호를 막을 수 있다.

## 5. 갈래 — 붙이는 자리·붙이는 법·약속

- **자리**: (가) 접두 `Quad0042 Slot:List: duplicate key …` — Rust/TS처럼 첫 토큰이라 눈·grep 모두 좋고, Luau의 `파일:줄: ` 접두 바로 뒤에
  선다. (나) 접미 `… duplicate key (Quad0042)` — 문장이 먼저 읽히지만 잘린 로그 끝에서 사라진다. 권고 **(가)**(대괄호 없이 — `[Quad0042]`는
  Roblox 출력창에서 검색어에 괄호가 끼어 불편하다).
- **붙이는 법**: 메시지 리터럴을 raise 줄에 통째로 남긴다는 결정은 유지한다. 그러면 ID도 그 리터럴 안에 **글자로** 들어가는 것이 가장
  단순하다 — `Err.errorBefore("Quad0042 Slot:List: duplicate key …", SURFACE)`. 헬퍼·상수 테이블은 두지 않는다(2026-09-08 결정과 같은
  이유: grep으로 메시지 → 자리를 찾는다). 유일성·형식은 **게이트**가 잡는다(아래).
- **레지스트리**: 한 파일(예: `scripts/error-codes.tsv` 또는 `docs/reference/errors/` 페이지 자체) — ID · 주어 · 짧은 뜻 · 문서 앵커.
  권고는 **문서 페이지가 곧 레지스트리**: `docs/reference/errors/<층>.md`에 `### Quad0042` 헤딩마다 한 절(증상·원인·고치는 법), 게이트가
  소스의 ID 집합과 헤딩 집합을 양방향으로 대조한다(없는 헤딩 → ERROR, 소스에 없는 헤딩 → WARN(폐기 표시 요구)). 별도 TSV는 두 소스가 갈리는
  길이라 안 둔다.
- **게이트**(`scripts/error-codes.py`, test.sh에 편입): (1) `errorBefore*`의 첫 인자가 `Quad\d{4} `로 시작하지 않으면 실패, (2) ID 중복 실패,
  (3) 문서 헤딩 대조, (4) 다음 번호 출력(`--next`). `doc-coverage.py`·`type-surface-check.py`와 같은 결.
- **약속(계약)**: ID는 **한 번 붙으면 안 바뀌고 재사용하지 않는다**(문구는 바뀔 수 있다). 그러면 "ID로 분기해도 되는가"가 생긴다 —
  (가) ID는 검색·문서 표면일 뿐 분기 금지(정책 (11) 유지), (나) ID는 안정 계약이라 `Fallback`의 `err`에서 `string.match(err, "Quad%d%d%d%d")`로
  분기해도 된다. 권고 **(나)** — 안 바뀐다고 약속해 놓고 분기를 금지할 이유가 없다; 다만 `err: any` 계약은 그대로라(테이블일 수 있다)
  레퍼런스에 "문자열일 때만"을 적는다.
- **범위**: 엔진이 내는 에러(Roblox 원시 에러, `TweenInfo.new` 거부 등)는 우리 것이 아니라 ID가 없다 — how-to 09가 "quad 에러인지 엔진
  에러인지 가르는 법"을 한 줄로 갖는다. `q.debug`의 `print` 경고(에러 아님)에는 ID를 안 붙인다(붙이면 "경고 코드"가 또 생긴다 — 필요가
  드러나면 그때).
- **롤아웃**: 222곳을 한 번에(sonnet 배치 — 기계적: 번호 부여 + 문서 절 생성 초안) vs 새 코드부터. 권고 **한 번에** — 반쯤 붙은 상태는
  검색 표면으로서 신뢰가 없고, 게이트 (1)을 켤 수 없다. 문서 절 222개는 초안을 기계로 만들고(메시지·주어·인용처) 뜻은 레퍼런스의 기존
  에러 표 문장을 옮겨 채운다.

## 6. 영향

- **레퍼런스 에러 표**: 유지하되 각 행이 ID를 앞에 달고 `errors/` 절로 링크 — 표는 "이 표면이 내는 에러 목록", `errors/`는 "그 에러의 설명".
- **how-to 09 색인 표**(docs-review 2-3): 이 계획이 대신한다 — 문구 색인이 아니라 ID 페이지.
- **스킬 문서**(`docs/skills/quad-ui-dev`)의 에러 문구 매칭 표: ID 열을 앞에 둔다.
- **CHANGELOG**: "Added — 모든 quad 에러 메시지가 `QuadNNNN` 식별자로 시작합니다(문구는 여전히 API 아님, ID는 고정)".
- **테스트**: 스펙이 `string.find(err, "must be a Source", 1, true)`처럼 문구 부분 문자열로 대조하는 곳은 그대로 동작(접두만 추가).
  `mock.assertBlamesUser`류 blame 검사도 무관.
