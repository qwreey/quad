# table-sim 소비 피드백 — quad 쪽 판정 (2026-10-12)

> **[2026-10-12 신설]** 레포 밖 첫 실제 소비자(Roblox 테이블탑 시뮬레이터 `table-sim`)가 quad `main` @ `1cc4a833`과
> Material 킷을 물어 쓰며 남긴 마찰 기록을 quad 쪽에서 판정한 문서. 원문은 레포 밖
> `/code/Projects/table-sim/.claude/feedback/`(색인 `README.md` — 보고서 `report-for-quad-2026-10-11.md`, 세부
> `quad-2026-10-11.md`·`material-kit-2026-10-11.md`·`material-kit-2026-10-12.md`·`toolchain-2026-10-12.md`)이고 여기
> 옮겨 적지 않는다. 그쪽 총평: quad 런타임 결함으로 막힌 일 0건, 버그 판정 0건 — 마찰은 문서가 말하지 않는 자리, 타입이
> 닿지 않는 자리, 소비자가 매번 다시 짜는 작은 것. 아래 번호는 그 보고서의 번호(R1~R11)와 킷 10-12 기록의 번호(M1~M8)다.
> 새 API·이름은 사용자 결정 전까지 제안이다.

## 이미 답이 있던 것 (table-sim에 돌려줄 답)

**R2 — props 안 인라인 `:Compute`가 strict에서 거부된다.** 알려진 한계다(`base/typing-limits.md` 8.13). 뿌리는 luau-lsp
1.69.0이 "다른 호출의 인자인 테이블 리터럴 안에서 호출에 넘긴 람다"의 매개변수를 기대 타입에서 정하지 못하는 것이고,
사용자 결정(2026-10-06)은 타입을 바꾸지 않고 luau-lsp를 기다리는 것이었다. 처방은 일곱 줄짜리 보조 함수가 아니라 매개변수
주석 한 번이다 — `Headline = item:Compute(function(self: q.StateData<TableInfo>): string return self:Get().name end)`
(2026-10-12 프로브로 통과 확인). 공개 문서에는 `docs/how-to/01-component-conventions.md`의 strict 절에 있었지만, table-sim의
에이전트가 읽은 스킬 문서에서는 이 내용이 v1 이관 참고서 안에만 있었다 — 아래 "고친 것"에서 옮겼다. 킷 갤러리의
`Common.text`를 내보내자는 제안은 그래서 필요 없다고 본다(툴체인 기록 2번의 "거꾸로 추론"도 같은 뿌리, 같은 처방).

**M1 일부 — "고르는 부품은 전부 필수 Source"라는 서술.** `Checkbox`와 `Switch`는 이미 제어 형태
(`Checked: State<boolean>` + `OnChange`, 아무것도 쓰지 않음)를 받는다(킷 `src/init.luau` 머리 주석 "API CONVENTIONS").
`Select`·`Radio`·`Slider`·`TextField`·`Chip.Filter`는 `Source`만 받는다 — 그쪽은 아래 결정 문항.

**R6 일부 — `D.New` 문서.** `docs/reference/roblox/02-d.md`의 `D.New` 절에 `D.New<<Part>>("Part")` 예와 "props는 `any`",
"파이프라인은 별칭과 완전히 같다"가 이미 있다. 빠진 것은 "GUI 밖 클래스에 State 묶기·이벤트·`Slot:List`가 실제로 돈다"는
확인된 사실의 서술이고, 그것을 지원 범위로 말할지는 아래 결정 문항.

## 고친 것 (결정 없이 닫을 수 있던 문서 공백)

- **R9·R10·R2 — 스킬 문서의 strict 진단 안내.** `docs/skills/quad-ui-dev/references/rules-and-invariants.md`에 2.6절을
  더했다: 없는 프로퍼티 키의 진단(`Expected this to be 'number', but got '"Bogus"'` = "그런 프로퍼티가 없다"), props 안
  인라인 `:Compute`의 진단과 주석 처방, 데이터에서 자식 여러 개를 만드는 정석(자식만 배열로 만들어
  `q.Slot<<Instance>>(kids)`에 넘기고 프로퍼티는 리터럴에). 셋 다 v1 이관 참고서 3절에만 있어서 이관하지 않는 소비자가
  만날 수 없었다. 2026-10-12 strict 프로브(luau-lsp 1.69.0 신 솔버)로 다섯 모양을 확인했다: Slot 초기 배열 통과, 끝 자리
  `table.unpack(kids)` 통과, 섞은 표 `D.Frame(props)` 거부, 없는 키 거부(위 문구 그대로), 주석 단 인라인 `:Compute` 통과.
- **R9·R10 — 공개 문서.** `docs/how-to/10-debugging-and-troubleshooting.md` 디버깅 체크리스트에 두 행(없는 프로퍼티 키,
  데이터에서 만든 자식 여러 개).
- **R7·R8·R11·M2·M5·M6·M1 — 킷 README.** 킷을 고치지 않고 쓰는 형제 배치와 rojo 예, 게임 설정 모듈이 물어야 하는 경로,
  커밋 고정 뒤 `pesde install`, 타입 이름 규칙(`Material.OverlayType`), 시트 자식 간격·수명, 값 계약과 서버 권위 패턴.
  킷 README(`quad-roblox-material/README.md`)의 설치와 설정 절(새 소절: 킷을 고치지 않고 쓰는 배치)·props 관례·새 소절
  타입 이름 규칙·시트와 내비게이션 드로어 절, 그리고 `src/init.luau` 머리 주석의 Types 관례에 반영했다. 근거는 소스 읽기다: `quad-roblox/src`는 quad_base를 직접
  require하지 않고 프로바이더로 주입받으며, 킷의 싱글턴은 `quad-roblox/luau_packages/quad_base` 링커가 가리키는 사본이라
  `quad-base/src`를 물면 다른 모듈 인스턴스가 된다. 같이 드러난 것 둘 — README가 "폼 컨트롤은 `Value`를 안 넘기면 내부 Source를
  만든다"고 뭉뚱그려 적었는데 `Select`·`Radio`·`DatePicker`는 필수라 문장을 갈랐고, 타입 이름은 일관된 규칙이 없어(값 모듈과 겹쳐
  접미가 붙은 것은 `OverlayType` 하나) 규칙이 아니라 실제 꼴의 표로 적었다. README의 `Select` 예는 strict 프로브로 확인했다
  (`Value`가 `Source<T?>`라 `q.Source<<string?>>(…)`로 만들어야 통과). 미확인: 새 복제본의 `pesde install` 산출물을 rojo가 그대로
  따라가는지는 table-sim의 보고("두 단계로 돌았다")를 인용했을 뿐 여기서 재현하지 않았다.

## 사용자 결정이 필요한 것

문항과 메인 의견은 `research/consumer-kits-plan.md` 5절 "table-sim 피드백 [2026-10-12]" 문단이 소스다(여기 복제하지
않는다). 요지만: 복제된 속성·자식 목록을 State로 읽어 올리는 표면(R1), 고르는 부품의 제어 형태 확장(M1), 킷 호스트
이름을 소비자 Modifier가 덮게 하기(R4·M8), `TextField` 글자 수 표시 끄기(M7), 월드 클래스의 타입 생성 범위(R3),
작업 트리의 버전 식별(R5), `D.New` 절에 GUI 밖 클래스 서술(R6).

## 조사만 한 것

**`ListItem`의 `Trailing`에 넣은 버튼을 누르면 행의 `OnClick`도 불리는가(table-sim 미확인 항목).** 코드 읽기 기준으로는 안 불린다.
`OnClick`이 있는 행의 호스트는 `TextButton`이고 `Activated`로 부르며, `Trailing`의 킷 `Button`도 `TextButton`이라 엔진 규칙(누름은
위에서부터 전해지다 첫 GuiButton에서 멈춘다 — `consumer-kits-studio-qa-2026-10-07.md`의 Studio 실측 절)대로 버튼에서 멈춘다. 행의
호버·누름·리플 표시도 버튼 위에서는 반응하지 않을 것이다. 목 백엔드는 이 규칙을 재현하지 못하고 킷 스펙에도 이 절은 없다 — 실기기
확인 대상.

**`TextField` 글자 수 표시의 정본.** 정본 클론이 스크래치에 없어 기억 기준이다: MDC-Android는 표시(`counterEnabled`·
`counterMaxLength`)와 입력 제한(`maxLength`)이 별개, Material Web은 `maxlength`만으로 표시가 붙음, Compose는 둘 다 없이 호출자가
`supportingText`에 직접 그림. 킷은 `src/TextField/Support.luau`에서 `MaxLength`가 있으면 무조건 표시를 만든다 — 끄는 선택지를
넣는다면 그 파일의 생성 분기와 `Ctx.luau`의 필드, `test/spec.textfield.luau`의 표시 절이 손댈 자리다.

## 조치 없음 (관측으로 받음)

성능 수치(R 관측 — `Slot:List`로 파트 2,000개, 개당 약 0.07 ms; `Instance.new` 대조가 없어 quad 몫은 미상), nil과 인스턴스를
오가는 State의 `Highlight.Adornee`, 한글 렌더, `ListItem`의 `Trailing`에 `D.Frame`으로 버튼 둘 묶기(M3), `Visible`은 Modifier로
먹는다(M4), 명령형으로만 닿는 것(`DragDetector:AddConstraintFunction`). 툴체인 기록 1번(주석 단 대입이 `keyof`를 `string`으로
넓힘)은 Luau 쪽 현상이고 quad 코퍼스에 같은 모양이 있는지는 보지 않았다. `upstream-candidates.md`(버전 붙은 데이터 변환
체인)와 `siblings-2026-10-11.md`(mrow·tbox·rbvm)는 quad 범위 밖이라 판정하지 않았다.
