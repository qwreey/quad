# table-sim 클라이언트 UI의 quad 사용 리뷰 — 2026-10-16

사용자 관찰에서 출발: *"table-sim 은 에이전트가 전부 코드를 썼는데, quad 를 쓴 부분에 있어서 결과가 조금 애매한게 많더라고. 특히 Bridge.luau … Store 이 거의 쓰이지 않는다던가, 옵저버를 sub 를 직접 해버린다던가 … Lobby.luau 까진 잘 쓰인것 같은데"*.
opus 하나가 quad 스킬·시작하기·레퍼런스를 기준으로 table-sim(`/code/Projects/table-sim`, HEAD `1087a1d`)의 `src/client/`를 읽기 전용으로 리뷰했다(런타임 실측 없음 — 코드 읽기). 메인이 핵심 사실(스킬 사본 정체, `hand[2]`, `:Subscribe()` 분포)을 확인했다.
줄 번호는 table-sim 작업 트리 기준. 앞선 판정은 `feedback/table-sim-2026-10-12.md`.

## 먼저 알아 둘 사실 둘

- **table-sim의 스킬 사본이 2026-10-11(`fce7a25`)에 멈춰 있다** — quad 고정은 `72c11d7`(10-13)로 올라갔는데 `.claude/skills/quad-ui-dev/`만 남아 10-12에 넣은 `rules-and-invariants.md` 2.6절이 닿지 않았다(메인 확인: `SKILL.md`·`rules-and-invariants.md`가 quad 본과 다름). 스킬 문장의 공백이 아니라 **배포 경로의 공백**.
- **컴포넌트 안의 `:Subscribe()`가 열아홉** — 전부 그 함수가 돌려주는 프레임에 묶을 수 있었다. 지금은 `App.mount`가 한 번만 불려 누수가 드러나지 않지만 다시 마운트되면 사본이 둘(같은 묻기 대화 상자가 두 번).

## A. 스킬에 넣을 것 (문안 초안은 영어 — 스킬 본문이 영어)

- **A1. Observer·Effect는 컴포넌트가 돌려주는 요소의 배열부에, `:Subscribe()`는 요소 없는 모듈 층에만.** 관측: `ui/Hud.luau` 98–105·154–166·188–212·215–239·242–266, `ui/HandStrip.luau` 46–58, `ui/SeatChooser.luau` 33–50, `ui/ToolRail.luau` 337–358(셋), `ui/PropsPanel.luau` 86–91·92–101·110–123·212·214–237·1221·1223–1227, `ui/PeopleSheet.luau` 105–120·436–444, `ui/BagSheet.luau` 244–443·445–452. 정당한 모듈 층 구독: `Main.luau:52`, `HandPick.luau` 146–152, `TableView.luau` 793–797, `HandView.luau` 883–887. 원인: SKILL.md 6.3과 rules 2.5가 두 선택지를 동등하게 적고 기본을 말하지 않음, 배열부 예는 code-recipes 5번 하나. 자리: SKILL.md 6.3 문단 교체 + rules 2.5. 문안:
  > **Where an Observer/Effect lives.** Inside a component, put every Observer/Effect you create in the array part of the element the component returns (or of one of its children) — it then lives and dies with that element. Reserve `:Subscribe()` for module-scope state layers that have no element (a network bridge, a selection model). Creating the handles at the top and the tree at the bottom is fine: list them at the end of the root's array part. A component-local `:Subscribe()` outlives its tree; call the component twice and both copies stay live.
- **A2. 일회성 요청을 `Source<Req?>`로 두고 그 Observer가 스스로 `nil`로 되돌리는 모양 = 정의되지 않은 동작(Observer가 자기 상류를 씀).** 관측: `ui/Hud.luau` 188–266(`TableView.askPile`·`askGive`·`askFlatten` — 요청마다), `ui/PropsPanel.luau` 212·142–145, `TableView.luau` 793–797·773. quad다운 모양: (가) 앱 수준 이벤트는 콜백 목록(quad는 Signal을 일부러 안 둠 — `base/architecture.md` 11번, `Bridge.on*`가 이미 그 모양), (나) 진짜 상태면 대화 상자의 단추·`OnClose`가 비우고 대화 상자는 `q.Effect`가 열고 cleanup이 닫음. 자리: SKILL.md §7 표 한 행 + rules 2.5. 문안:
  > | A one-shot request modelled as `Source<Req?>` that its own Observer consumes and resets (`ask:Set(nil)` inside `ask:Observer`) | Undefined behaviour — an Observer feeding its own upstream (`q.debug` warns once per handle) | App-level events are callbacks (`onAsk(fn)` registries — quad has no Signal by design); if the request is real state, clear it from the dialog's own buttons/`OnClose` and open the dialog from a `q.Effect` whose cleanup closes it |
- **A3. 바뀌는 대상에 엔진 신호를 붙였다 떼기 = `q.Effect`의 의존성 + cleanup.** 관측: `ui/PropsPanel.luau` 238–246(0.25초 영구 폴링), table-sim 보고 C1(*"신호를 붙였다 떼는 쪽이 더 번거로웠다"*). quad엔 이미 있다(시작하기 08 §4 "Ref를 의존성으로", how-to 04 §4) — 스킬에 레시피가 없음. 모양: `q.Effect(function() local part = propsPart:Get(); if not part then return nil end; read(); local c = part.AttributeChanged:Connect(read); …; return function() c:Disconnect() … end end, propsPart)`를 Props 프레임 배열부에. (묶음 구성원 속성은 여전히 R1 빈칸.) 자리: code-recipes 새 레시피 "Engine signal on a target that changes" + SKILL.md 6.3 끝. 문안:
  > When the thing you listen to is itself a State (the selected part, the hovered instance), do not poll and do not juggle connections by hand: make it the `Effect`'s dependency, connect inside `fn`, disconnect in the cleanup — the cleanup runs before every re-run, so switching targets detaches the old one.
- **A4. Observer로 맞추지 말고 파생 — 서로 배타인 플래그는 enum Source 하나, 직전 값 붙들기는 `previous`.** 관측: `ui/ToolRail.luau` 337–358(서로 끄는 Observer 셋), `HandPick.luau` 32–39·146–152, `ui/Hud.luau` 97–105(`lastPeek`), `ui/SeatChooser.luau` 31–50(지역 `lastId`·`lastSeat`). 자리: SKILL.md 2.1 끝 + 6.3. 문안:
  > `previous` is the value this node returned last time — use it for continuity ("keep the last non-nil", accumulate), never to own resources. Two flags that must never be true together are one `Source` of an enum, with the flags derived from it — do not keep them in sync with Observers that write each other.
- **A5. 흐려진 뒤 `Visible = false` — `task.delay`가 아니라 Tween `Started`/`Completed`.** 관측: `ui/Hud.luau` 150–166(주석이 "거의 투명한가를 물을 수 없어 시간을 잰다"), `ui/HandStrip.luau` 44–58. 자리: SKILL.md 6.1 `btnColor` 경고 아래. 문안:
  > To hide an element after it has faded out (an invisible-but-Visible GuiObject still eats clicks), do not time it with `task.delay`: drive a separate `shown` Source from the tween's own `Started` (`to` = visible target → `true`) and `Completed` (`to` = hidden target → `false`) and bind `Visible = shown`.
- **A6. 여러 루트를 내놓는 컴포넌트와 나중에 붙는 자식 = `Slot`.** 관측: `ui/ToolRail.luau:759` `return { rail, panel, liftPanel }`, `ui/HandStrip.luau` 26·62가 배열 반환 → `ui/Hud.luau` 503–508이 `tools[1..3]`, `hand[1]`, `hand[2]`로 손으로 폄(**`hand[2]`는 10-15 `1dbfd2a` 뒤로 `nil`**); `.Parent =`로 끼우기 셋(`ui/App.luau` 33–82 알림, 122–182 Highlight, `ui/ToolRail.luau` 216–226). 자리: SKILL.md 3.1 끝. 문안:
  > A component that renders several siblings returns `q.Slot<<Instance>>({ a, b, c })` (a DOMless fragment, §4.1) and the caller places it as ONE array item — never return a Lua array for the caller to index (`parts[1], parts[2]` silently becomes a `nil` when the component drops one). Children added later go through a Slot (`slot:Add`), not `child.Parent = quadMadeFrame`.
- **A7. 상태 층은 `q.Store`, 설정 모듈이 다시 내보낼 타입 목록.** 관측: `Bridge.luau` 26–42 Source 아홉, `TableView.luau` 69–197 서른, `ui/PropsPanel.luau` 36–130 폼 Source 마흔 남짓(초기화가 Observer 셋에 흩어짐), `ui/Layout.luau`. Store는 SKILL.md 1.2 한 줄뿐. table-sim `Quad.luau` 6–16은 `State`·`Source`·`Slot`·`SlotItem`·`KeyGone`만 다시 내보내 R2 처방(`self: q.StateData<T>`)을 못 씀. 자리: SKILL.md 1.1 + code-recipes 새 레시피 "State layer (RemoteEvent → Store)". 문안(1.1):
  > The setup module re-exports at least `State`, `Source`, `Slot`, `SlotItem`, `KeyGone`, `StateData`, `Store`, `Ref`, `Observer`, `Effect`, `Context`, `Provider` — `StateData` is what you annotate an inline `:Compute` parameter with, so leaving it out forces helper wrappers.
- **A8. 엔진이 계산한 값은 한 번 Source로 들여오고 크기는 Compute로.** 관측: `ui/PropsPanel.luau` 1207–1221(`FindFirstChildOfClass` + 연결 둘 + 명령형 `scroll.Size`), `ui/ToolRail.luau` 369–380, `ui/PeopleSheet.luau` 414–415·`ui/BagSheet.luau` 257–258(열 때 한 번만 읽음). 문안:
  > Engine-computed read-only values reach the graph through `q.OnChange(name, fn)` / `q.Out` (the read surface includes read-only properties) or one module-level Source fed by one connection; a size that depends on them is a `:Compute` bound as a prop. Do not `FindFirstChildOfClass` + connect + assign `inst.Size` by hand.
- 덧붙임: 섞인 props 표 + `table.insert` + `D.Frame(t)`(`ui/SeatChooser.luau:55`, `ui/ToolRail.luau` 651·661, `ui/PropsPanel.luau` 293·353·409·563, `ui/PeopleSheet.luau` 60·156, `ui/FeedbackButton.luau:48`)와 `shape(props)`(`ui/ToolRail.luau` 84–87)는 현 rules 2.6·SKILL 3.3이 이미 답함 — 사본 갱신으로 닫힘.

## C. quad에 없어서 어렵게 돌아간 것

- **C1. 흩어져 만든 Observer·Effect·연결을 루트에 한 번에 묶기** — 오늘도 루트 배열부 끝에 나열하면 된다("에이전트가 몰랐다" 쪽). 그래도 `q.Spread` + `:Add` 누적(사용자 아이디어 — `research/component-flatten-sugar-plan.md` 5절)이 실제로 도움됐을 자리 다섯: `ui/Hud.luau`(Observer 다섯 97–266, 프레임 268, 배열 반환 손으로 펴기 503–508), `ui/ToolRail.luau`(Observer 셋·카메라 연결·루트 셋), `ui/PropsPanel.luau`(Observer 여섯·연결 둘·폴링), `ui/HandStrip.luau`·`ui/SeatChooser.luau`. **ToolRail은 "루트 여럿 + 딸린 Observer"를 한 값으로 내놓는 자리라 Slot으로는 안 된다**(Slot은 Observer/Effect 원소를 `Quad0238`로 거부) — `Spread`만 되는 진짜 빈칸. 설계 시사점: (가) 찾은 자리 전부 누적이 루트 리터럴보다 먼저 끝남 → "놓이기 전까지만 `:Add`, 놓이면 얼림"으로 충분(사용자 보충과 일치), (나) 묶음 안 Observer는 묶음을 **놓은 요소**의 수명에 묶임(컴포넌트 자신의 루트가 아님) — 문서 한 줄, (다) 가장 흔한 내용물은 Observer와 인스턴스뿐, 문자 키 자리는 없었음 → `Spread<Ty>`의 props 타입이 없어도 이 용도는 손해 없음.
- **C2. 값이 실제로 바뀔 때만 내려보내는 파생(distinct) — quad에 정말 없다(보류된 빈칸).** 다섯 번: `Bridge.luau` 28·192·198, `ui/SeatChooser.luau` 31–50, `ui/BagSheet.luau` 59–60·251–252, `HandPick.luau` 126–142, `ui/PropsPanel.luau` 184–190. `:Compute`는 결과가 같아도 통지한다(시작하기 08 §4); `base/debounce-throttle-plan.md`가 "게이트에 섞으면 eager — 필요하면 별도 콤비네이터"로 남김. 지금 관용구는 "Observer가 **다른** Source에 `SetIfChanged`"(정상 경로) — 스킬 레시피감. 별도 콤비네이터는 사용자 결정.
- **C3. 앱 수준 이벤트** — 일부러 없음(Signal 기각, 콜백 목록이 정답). `q.OnEvent`와 무관. 스킬이 말해 줄 것(A2).
- **C4. 한 항목이 서로 다른 부모 둘에 인스턴스를 갖는 목록**(`HandView` 카드 = 카메라 폴더의 `Part` + PlayerGui의 `SurfaceGui`) — 새 빈칸 후보, 확신 낮음; `D.New`가 `any`(R3, 기보고)라 명령형이 지금은 합리적. 3D `*View`의 `Instance.new`도 같은 이유로 오히려 타입이 단단함.
- **C5. 쓰는 쪽 일괄 갱신** — 관측만(Bridge 193–198, 순서로 해결, 아픈 증상 없음).
- **C6.** `slot:Lazy`가 들어맞는 자리는 못 찾음, `Split`은 table-sim 컴포넌트에 Modifier 경계가 거의 없음, `q.OnEvent`는 `ui/CardFace.luau` 78–92 한 곳(근거 약함).

## D. 총평
